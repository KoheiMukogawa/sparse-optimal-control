## 2026-06-13 セッション7（L字3者比較＝実施／L1チャタ発見・原因と対策をsimで立証）

- 床で Kanayama/L2/L1(λ=0.3) を **L字**（直線1.5m→左90°→直線1.5m, v_r0.1, N15）各1本
  実走（許可のもと）。bag: `results/2026-06-13_Lturn_{kanayama,l2,l1}`。
  まとめ: `results/2026-06-13_Lturn_compare.md`、図 `results/2026-06-13_Lturn_plot.png`。
- **予想と真逆: L1 がコーナーで bang-bang チャタリング**。Σ|u| は L2 4.54 < Kanayama 4.88
  ≪ **L1 20.71**、ω符号反転は L2/Kanayama 0回 vs **L1 15回**・41%が±2.0飽和。L2 が
  追従最良（odom RMSE 1.42cm）・操舵最少。Kanayama はコーナーを外へ膨らむ(RMSE 11.3cm)。
- **原因を sim で立証**（`rover/sim_delay_probe.py`）: 理想 sim では L1 もクリーン
  (Σ|u|4.4/反転0)。**入力遅延2step(~200ms)を入れると L1 のみ Σ|u|18.5/反転19 ＝
  実機(20.7/15)と定量一致**。L2 は全遅延で反転0。機序＝L1の bang-bang が遅延下で
  限界振動化（スライディングモード的チャタ）。L1 は求解時間が L2 の2倍＝自分で遅延を増やす悪循環。
- **対策も sim で確認**: `mpc_core.MPCFollower` に `move_suppress`（Δu率ペナルティ・
  既定0で後方互換）追加。L1+ms=2.0 は遅延2でも Σ|u|5.0/反転1、理想時も ω0率93%で
  スパース性維持。`mpc_follower.py` に `move_suppress` パラメータを通済み（実機検証で即使用可）。
- **位置づけ**: 「L1優位」ではなく「ナイーブな L1 hands-off は実機遅延下でチャタ＝sim非自明・
  実機検証必須」を実証。中間発表の良い知見。現状の総合最良は L2-MPC。
- **次**: 修正版 L1（`-p move_suppress:=2.0`）を RPi 配置→**L字実機再走でチャタ消失を実測確認**
  （要ユーザー許可）。これで「問題→原因→対策」を実機で閉じる。
- **外部計測(真値)取得済み**: L2 最良(終点ゴール直下2cm・傾き0°・小半径でキレイに90°)、
  **L1 はジグザグを目視確認**(コーナー135°行過ぎ→右戻しを約10回反復し到達・最終向き右40°)、
  Kanayama は大周り(中心線左5cm・9°左)。全器 1st leg 134-136cm=lookahead15cm手前で旋回開始。
  → **L1チャタは bag(ω反転15回) と外部目視(ジグザグ約10回) の両方で一致**。直線(S6)でL1最良
  だったのと好対照＝操舵不要なら優秀・持続操舵で破綻。

  ゴール到達後killのため。mpc_follower は try/except 済み）。気になれば後で堅牢化。
