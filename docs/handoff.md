### 入力遅延のodom基準実測（R5 の暫定版・R5 本体ではない）

`rover/measure_delay_real.py` を新規追加し、接地・その場旋回でωステップ応答を n=20 計測。
詳細は `results/2026-09-14_delay_odom/notes.md`（results はgitignore）。

| 指標 | 中央値 | 四分位 |
|---|---|---|
| むだ時間 D（モデル当てはめ） | **135.0 ms** | 100.0〜140.0 |
| むだ時間 D（閾値法・0.5°） | 174.6 ms | 151.1〜191.2 |
| 時定数 τ | **測定不能**（分解能以下） | — |
| 定常角速度 ω_ss | 0.500 rad/s（指令0.5に一致） | — |

**採用値は D ≈ 135 ms。** 閾値法が高く出るのは構造的なもので、内訳が計算で合う:
閾値0.5°到達に 17.5ms（ω=28.6°/s）＋ 量子化期待値 16ms（32msの半分）→ 135+17.5+16≈168.5ms
で実測174.6msと一致。先行のω基準版（t10 中央値 152.5ms）も両者の中間に来て矛盾しない。

**τ は20試行すべて格子下限に張り付いた** ＝ 立ち上がりが odom の分解能(31.3Hz=32.0ms)より
速く、一次遅れとして検出できない。「τ<32ms」が正しい報告で、応答は実質的に純粋な
むだ時間として振る舞う。

**閉ループ実効遅延の見積り**: 本計測は `ros2 topic pub` から直接指令しており **MPC求解を
含まない**。135ms ＋ 求解p95 22ms（同日R4実測）≈ **157 ms**。

**5.6節の「約200ms」をこの値で書き換えてはいけない。** R5 の設計（outline.md:781）は
「指令 → **カメラ真値**の角速度応答の時間差」であり、本計測は odom 基準で定義が違う
（odom自身の報告遅れとサンプリング分解能が乗る）。現時点で言えるのは
**「暫定測定が推定値と同オーダーであることを確認した」まで**。R5 は未完了のまま。

**方法上の知見**: 初版はω（角速度）の閾値交差で測ったが、**ωは31ms毎のエンコーダ差分＝
微分量でノイズが大きく**、閾値を跨いで上下するため t63 に 812ms のような異常値が出た。
θ（積分量）に変えるとノイズσはほぼ0°になり安定した。**実機のステップ応答はωでなくθで見ること。**

- **走行中（step≥1）は一度も24msを超えていない。** 0.1s周期に十分収まる

戻った時点で経過が閾値を跨ぐと出る偽陽性。閾値のすぐ手前なのでodom到着の位相次第で
出たり出なかったりする。影響は零指令1回とcmd_delayのreset（走行開始前・バッファ空）で無視できる。
**実機のodom断を疑って追いかけないこと。**

**L1の求解特性（副産物）**: 初回 iters=300 / 466〜486ms、走行中 p95 **42〜44ms**。
同日のL2は初回 iters=200 / 264〜386ms、p95 **21.95ms**。**L1はL2の約2倍遅く**、
5.2節「L1は自ら遅延を増やす」と整合する。いずれも初回を除けば0.1s周期に収まる。

**`--pause` を run_batch に追加**した。`--manual` は終点入力が必須で、外部計測をしていない
場合に数値のでっち上げを迫る構造だった（同日R4でそれが起きた）。`--pause` はEnter待ちのみで
`truth_*` は欠測のまま残す。テスト171本 all green。

### 詰まったところ（次回のため）

- `set -u` は ROS の `setup.bash` と衝突する（`AMENT_TRACE_SETUP_FILES: unbound variable`）。
  source の間だけ `set +u` にする
- **`ros2 run` 経由で起動すると `$!` がラッパーのPIDになり、kill してもノード本体が生き残る。**
  ノード本体（`install/lightrover_ros/lib/lightrover_ros/<node>`）を直接 `python3` で
  起動すればPIDが実体と一致する
- **`pkill -f` / `pgrep -f` はSSHのリモートコマンド文字列自身にマッチして自滅・誤検出する。**
  PID指定で kill するか、`[i]2c_controller` のようなブラケット回避を使う
- 非対話シェルからバックグラウンド起動したプロセスは **SIGINT が無視として継承され
  `trap` で上書きできない**（POSIX）。スクリプトの停止テストは SIGTERM で行うこと。
  端末で前面実行すれば Ctrl-C は正常に効く
- `vcgencmd` が `VCHI initialization failed` で使えない（低電圧警告をCLIで確認できない）。
  ユーザーを `video` グループに入れれば直るはず・未対応
