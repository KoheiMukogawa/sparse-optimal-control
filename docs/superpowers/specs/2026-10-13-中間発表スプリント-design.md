## 真値計測の方式 —— 方眼紙＋ペン軌跡

カメラ俯瞰（AprilTag・C270）は使わない。**走行面を大判紙にし、
駆動軸中心に垂らしたペンで軌跡を描かせ、方眼から直読する。**
これは `specs/2026-09-12-大学実験環境への移行-design.md` で承認済みの方式であり、
実装（`run_batch.py --manual`、`exp_metrics.manual_metrics`）も完了している。

**この方式を採る理由**: 読み取りに画像処理が一切要らない。
コースを方眼の格子線に重ねる設計のため、

- 第1直線 `(0,0)→(1,0)` は **x 軸そのもの** → 横偏差 = 軌跡の y 座標を直読
- 第2直線 `(1,0)→(1,1)` は **x=1 の格子線** → 横偏差 = `x−1` を直読

となり、「軌跡が格子線から何マスずれているか」を数えるだけで済む。
**1走行3〜4分、Phase 2 の12走行で約45分。** 精度は x,y が数mm・θ が1°以下で、
廃したカメラ（2.5cm・1.6°）より良い。

**前提条件（崩すと数値が無効になる）**:

1. ペンは**駆動軸中心**に垂らす（ずらすとレバーアーム分の誤差が旋回時に乗る）
2. 走行面は**無地の大判紙に自分で10cm格子を墨出し**（2m角推奨）。
   **方眼模造紙の継ぎ合わせは継ぎ目で座標系がずれるため不可**
3. 真値RMSE の対象は **Phase 2 の12走行に限定**（Phase 3 以降は終点誤差のみ）
4. 紙は四隅＋辺の中点を格子状に固定し、走行間に目視確認

**カメラ方式との非可比性**: 手計測RMSE（紙面基準・10cm間隔の空間サンプリング）と
カメラRMSE（開始pose基準・時間サンプリング）は定義が異なる。
4.3.5節に既に明記済みであり、**方式間で直接比較しない**。

### R5（入力遅延の直接実測）の手順判定

当初手順はカメラ真値の角速度応答を前提としていたため、代替手順を Phase 0 で判定する。

1. **第1候補: odom の ω 立ち上がりで測る。** odom は滑りで絶対値が歪むが、
   立ち上がり時刻は車輪エンコーダ由来なので取れる可能性がある。
   そもそも制御ループが見ている遅延は「指令 → odom 反映」なので、
   **むしろこちらが測るべき量**かもしれない。
   ただし odom パイプライン自体の遅延と切り分けられるかが未確認
2. **第2候補: スマホ240fps 動画。** 指令送出と同時に LED を点けて時刻同期し、
   車輪の動き出しをコマで読む

1 が使えるかを Phase 0 で判定し、駄目なら 2 に切り替える。

**なお 2026-09-17 に表5.7b（むだ時間135ms＋求解40ms＝約175ms）が既に実測済み**なので、
R5 で新たに閉じるのは **odom パイプライン自体の遅延の切り分け**である。
