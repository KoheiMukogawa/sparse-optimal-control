# カメラ真値計測パイプライン＋実験完全自動化 設計（2026-07-16 承認済み）

## 背景・目的

- odom は滑りを見られない（7/15実機バッチ: 真値の終点誤差は odom RMSE の5〜10倍、
  全走行がコーナー外側へ流れる系統誤差を odom は全く検出せず）→ 外部真値が必須。
- 手計測（床テープ＋メジャー）は1本ごとに数分かかり、反復数を増やせない。
- **最終形**: 走行 → カメラ真値を自動保存 → 自動で原点復帰 → 次走行、の
  一括許可ループ。S8で挙げた物理側2課題（①原点復帰・④真値計測）を両方閉じる。

## 決定事項（ブレインストーミング結果）

- スコープ: **完全自動化まで**（ただし3フェーズに分割、各フェーズ単独で価値を持つ）
- カメラ: **開発は手持ちの C270**（720p・対角55°、縮小エリアで Phase1-2 開発）、
  **本番（Phase 3・全コース2.2m四方）は対角90°以上・1080p の広角USBカメラを導入**。
  カメラ差し替えは camera_truth.yaml のキャリブ値更新のみ。
- アーキテクチャ: **案A＝ラップトップ集中＋UDPブリッジ**。
  DDS（ラップトップ↔RPi、6/12以来未解決）を完全回避。
  検出・記録・復帰誘導の計算は全てラップトップ、RPi側追加はブリッジ1ファイルのみ。
- 安全: **バッチ開始時に一括許可[y/N]＋有人監視＋qキー即停止**。無人運転はしない。

## コンポーネント

| ファイル | 役割 | 場所 |
|---|---|---|
| `rover/truth_core.py` | タグ検出→カメラ姿勢→ロボットpose。純ロジック（I/Oなし） | laptop |
| `rover/truth_offline.py` | Phase1: 動画ファイル→(t,x,y,θ)CSV＋指標のCLI | laptop |
| `rover/truth_live.py` | Phase2: ウェブカメラ→ライブ検出→走行ごとCSV。start/stop API | laptop |
| `rover/homing.py` | Phase3: カメラposeで原点へ誘導（follower_core流用） | laptop |
| `rover/udp_twist_bridge.py` | Phase3: UDP {v,ω,seq}→rover_twist。watchdog 0.5s→停止 | RPi |
| `configs/camera_truth.yaml` | タグID/サイズ・床タグ実測座標・カメラ内部パラメータ・UDP宛先 | — |

既存改修: `exp_backends.py`（真値記録hook）、`exp_metrics.py`（真値指標）、
`run_batch.py`（autoループ・新CSV列）。

## 座標系・キャリブレーション

1. カメラ内部パラメータ: チェスボードで1回キャリブ（歪み補正込み）。
2. **床基準タグ4枚**（tag36h11・15cm角）をコース四隅付近に貼り、実測座標を
   yaml に記録 → 毎セッション自動検出し **solvePnP でカメラ外部姿勢**を推定。
   4枚未検出ならセッション開始拒否。
3. **ロボット上面タグ**（12cm角・床から高さh≈13cm）は床ホモグラフィだと
   コース端で最大±9cmの視差誤差 → **光線と平面 z=h の交点で厳密に解く**。
   θ もタグ向きから同様に算出。
4. 出力座標系は経路と同じコース座標系（原点=走行原点、x=第1直進方向）。
   7/15の手計測（ゴール原点系）とは平行移動のみで直接比較可能。
- 精度目標: **静置照合でメジャー実測と±1〜2cm一致**（Phase1で検証してから真値認定）。

## データフロー（走行1本・Phase2以降）

```
run_one開始 → truth_live.start(outdir/truth_<cond>_r<rep>.csv)
  → [既存] bag record → follower起動 → 到達検知 → 停止 → bag回収
  → truth_live.stop()
  → runs.csv に既存指標＋新列:
     truth_end_dist_cm / truth_rmse_cm / truth_end_x / truth_end_y / truth_end_theta
     （end_x/y/θ は 7/15 手計測と同じ定義）
```

- CSV行: `(t, x, y, theta, n_tags, quality)`。欠測は欠測行として記録（補間しない）。
- 時刻同期はしない（終点誤差・軌跡RMSEに不要）。必要になったらノード起動時刻で推定。
- `--save-video` で検証用に生動画保存（既定OFF・最初の数本のみ使用）。

## 自動原点復帰（Phase 3）

- カメラposeを状態量に、follower_core の Kanayama 誘導＋ゴール判定を流用して
  「現在地→原点」直線経路を追従、最後にその場旋回でθ合わせ。
- 到達判定 **±3cm・±5°**（手置き同等以上。復帰誤差＝次走行の初期poseはカメラが
  記録するので実験データ上も既知）。
- v=0.08 / ω上限1.0 / タイムアウト30s / 1回リトライ → 失敗時はループ停止し人へ。
- 指令経路: laptop → UDP → udp_twist_bridge → rover_twist。

## 安全設計

1. qキー即停止（停止指令送信＋既存KILL_CMDでfollower kill）
2. ブリッジwatchdog: UDP 0.5s途絶 → ゼロ速度配信（WiFi断・laptopクラッシュ対策）
3. pose途絶 1s → homing中断・停止（オクルージョン対策）
4. コース外接矩形＋30cm余白を逸脱 → 即停止
5. 走行フェーズは従来どおりRPi内で完結（既存の到達停止・odom途絶停止が生きる）。
   ブリッジが速度を流すのは復帰フェーズのみ。
6. 走行失敗時は ok=false で次へ（連続2本失敗でループ停止）。

## エラー処理

| 異常 | 挙動 |
|---|---|
| カメラ切断/フレーム失敗 | エラー記録し走行続行（bagは残る）。autoループは停止して人へ |
| 床タグ検出不足 | セッション開始拒否（照明・貼り直し促し） |
| ロボットタグ瞬断 | CSV欠測行。homing中は1s超で安全停止 |
| UDP順序乱れ | seqで古い指令破棄 |

## テスト方針

- `truth_core`: **合成画像テスト**。既知のカメラ姿勢・タグ配置からOpenCVで
  レンダリング→検出poseが±数mm一致（視差補正の正しさを担保）。
- `homing`: SimBackendのプラント流用＋カメラ観測の模擬（ノイズ・欠測・遅延）で
  任意初期姿勢から±3cm/±5°収束を確認。
- `udp_twist_bridge`: watchdog/seq破棄をROS非依存関数に切り出して単体テスト。
- 実機E2Eはフェーズごとに1回、従来どおり許可を取る。

## フェーズ計画

1. **Phase 1**: truth_core + truth_offline。iPhone動画→CSV。静置照合で±1〜2cm
   確認して真値認定（ロボット・購入品不要）。
2. **Phase 2**: usbipd＋C270で truth_live、run_batch統合（運転はEnter式のまま）。
   縮小エリアでE2E。
3. **Phase 3**: 広角カメラ導入、ブリッジ＋homing＋一括許可autoループ＋安全機構。
   homing単体の有人確認 → 短いautoループ → フルバッチ。
