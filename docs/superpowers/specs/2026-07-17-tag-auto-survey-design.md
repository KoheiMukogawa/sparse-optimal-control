# タグ自動サーベイ設計（カメラ真値のメジャー実測レス化）

日付: 2026-07-17 / 状態: 承認済み
前提: specs/2026-07-16-camera-truth-pipeline-design.md（Phase 1〜3 実装済み）

## 背景と目的

自宅環境のため毎セッション床を全撤収する（タグもコーステープも残せない）。
現行はタグ中心をメジャーの2点測位で実測して configs/camera_truth.yaml の
floor_tags に手記入する方式（1回15〜20分）で、タグが動くと solvePnP は
**検出成功のまま黙って間違った値を出す**（7/17 に実際に発生）。

目的: **毎セッション、タグを適当に置いて1コマ撮り、コマンド1発で floor_tags
を自動生成する**。メジャー実測・床の原点テープを廃止し、「タグが動いた」
という故障モードを構造的に消す。

不採用案:
- 一体型タグシート: 走行面が変わる（滑り計測の研究と干渉）・車輪が引っ張る
  シワで相対位置が狂う・製作が重い
- 手計測継続＋残差チェックのみ（案A）: 検知して止まるだけで測り直しは残る。
  ただし合成テストで精度が出ない場合の撤退先として保持

## 毎セッションの運用フロー

1. タグ4枚を前回の写真とだいたい同じ配置で床に置く
   （コース南側に tag0・tag3、北側に tag1・tag2。メジャー・テープ不要）
2. `uv run python rover/survey_tags.py`（C270 の1コマ。`--image <file>` も可）
   → floor_tags を計算し yaml を自動更新、残差とコース配置図を表示
3. ロボットをカメラに写る適当な場所に置く → homing が原点(0,0,0)へ自動搬送
4. いつもの `run_batch --auto`

床に残すものゼロ・人手の計測ゼロ。

## カメラ

**C270 を使う**（iPhone 12 は不採用）:
- ランタイム（truth_live）と同じカメラ・同じ視点の1コマでサーベイするため、
  キャリブ偏り等の系統誤差が打ち消し合う方向に働く（iPhone だと独立誤差の加算）
- iPhone は未キャリブで、レンズ切替・AF で内部パラメータが動きやすい
- 毎セッションのファイル転送が不要
- `--image`＋K指定は残す（将来の多視点強化の入口）

## 座標系の規約（タグが座標系を定義する）

- **+x = tag0中心 → tag3中心 の方向**
- **原点 = tag0中心 + 0.20m·(+y)**（+y は +x から反時計回り90°＝コース側。
  z上向きの右手系）
- 7/16 の実配置（tag0=(0,-0.2), tag3=(1.194,-0.297)）の規約化。タグを似た
  配置に置けばコースはほぼ同じ場所に再現される
- path yaml・truth_core・homing・run_batch は floor_tags を読むだけなので
  **既存コード無変更**（座標系の意味が「テープ実測の系」→「タグが張る系」に
  変わるだけ）。走行原点の物理位置はタグから毎回導出＝原点テープ不要

## アルゴリズム（rover/survey_tags.py）

1. **初期解**: detect_tags の4隅（正準順）× 黒枠実寸 floor_tag_size_m の
   正方形で、タグごとに SOLVEPNP_IPPE_SQUARE → カメラ座標系の各タグ姿勢。
   （Phase 1 で IPPE を避けたのは4タグ広域PnPの話。ここは初期値用途）
2. **精緻化**: 未知数=カメラ姿勢6＋各タグ(x,y,yaw)×4、拘束=全タグ z=0 平面・
   実寸 s の正方形、で全16隅の再投影誤差を scipy.least_squares で最小化。
   ゲージは tag0 中心固定・tag0→tag3=+x で潰す。単体PnPの奥行きノイズは
   平面拘束＋16点同時フィットで抑える
3. **書き出し**: 上記規約で座標変換し、configs/camera_truth.yaml の
   floor_tags を日付コメント付きで更新

設定追加は1キーのみ: `floor_tag_size_m`（印刷黒枠の実測値、定規で1回。
スケール誤差はここに集約。±0.5mm → 1.2m 先で4mm。同一印刷ロットで共通）

## 安全チェック（黙って間違わせない）

survey_tags.py 内:
- **最適化残差**: 再投影RMSが閾値（1px目安・合成テストで確定）超 → CalibError
- **コース内包**: L字経路全点がタグ凸包の内側か。外挿地帯（7/16 に10-15cm
  誤差の実績）にはみ出したらエラーで拒否＋どのタグをどちらへ動かすか表示
- **共線・面積**: 4枚ほぼ一直線・凸包過小を拒否（truth_core.py の既存判定と同思想）

ランタイム側（truth_core.solve_camera_pose）にも追加:
- **再投影残差チェック（2px超で CalibError）**。サーベイ後にタグが動いた・
  yaml が古い・解像度違いを走行前に止める（案Aに戻る場合も単独で価値あり）

## テスト計画（実機前に合成で全部検証）

tests/synth_scene.py（tag_corners3d / render_scene）を流用:
1. 既知配置を合成 → サーベイ → floor_tags 復元誤差 **≤1cm**。カメラ高さ・
   傾き・タグ配置・±0.3px 隅ノイズを振って統計
2. 復元 floor_tags で既存 robot_pose を回し、ロボット位置の最終誤差 ≤1cm
   （サーベイ誤差の伝播込み E2E）
3. チェック系: 共線配置・コースはみ出し・高残差が正しく CalibError になる

**撤退基準**: 合成で1cm超 → C270 複数フレーム平均を追加 → それでも超なら
案B放棄・案Aへ（solve_camera_pose の残差チェックだけ残す）。

**実機初回のみ**軽い静置照合: サーベイ → 測りやすい既知点2点にロボット静置 →
表示値と実測の一致確認。合格後のセッションは完全計測レス。
