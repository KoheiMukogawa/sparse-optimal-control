# スパース最適制御シミュレータ C 実装 設計書

- 作成日: 2026-08-30
- 目的: wolfSSL Japan インターンシップ応募用の C/C++ サンプルプログラム
- 公開先: 新規の公開 GitHub リポジトリ（本リポジトリとは分離。仮称 `sparse-mpc-c`）

## 1. 背景と目的

wolfSSL Japan のインターン応募にあたり、C/C++ のサンプルプログラムを提出する。
募集要項は「自分のスキルや興味の対象が現れるもの」「完成度は問わない」。

卒業研究（農業ロボットの経路追従におけるスパース最適制御 / Maximum Hands-off
Control）の中核である MPC を、**外部ライブラリに一切依存しない C99** で書き直す。
これにより次の2つを同時に満たす。

1. **提出物として**: 数値最適化アルゴリズムを自前で実装でき、動的メモリ確保なし・
   依存ゼロという組込み向けの規律で C を書けることを示す
2. **研究への転用余地として**: 卒論の評価軸のひとつ「計算負荷」は現在
   Python + cvxpy + OSQP で測っており、アルゴリズム本体のコストと Python 側の
   オーバーヘッドが分離できていない。C 実装はこれを分離する土台になる

### 1.1 研究への寄与の範囲（正直な線引き）

**寄与する**: 計算負荷の章のみ。現行ベンチ（`results/2026-06-13_rpi_bench/`）は
N=30 で L1 の p95 が 29.2ms、L2 が 17.7ms であり、制御周期 100ms に対して 3〜5 倍の
余裕が残っている。つまり **「N≤30」は測定範囲の上限であって性能限界ではない**。
C 実装はこの境界を素の数字で引き直す手段になる。

**寄与しない**: RMSE・消費エネルギー・入力スパース性は制御則の性質であり、
実装言語を変えても一切変化しない。新しい制御理論的知見は出ない。

**現時点のブロッカー**: RPi4 が起動不能（`results/2026-08-01_rpi_boot_diag/notes.md`。
新規イメージでも非起動）。論文グレードの実機ベンチは実機復旧が前提。
したがって本設計では**実機ベンチをスコープ外**とし、ラップトップ上での比較に留める。

## 3. 移植対象の定式化

`rover/mpc_core.py` の定式化をそのまま移す。

### 3.1 変数と力学

- 状態 `z = (x_e, y_e, θ_e)`（Kanayama 誤差、ロボット座標系）, `nx = 3`
- 入力 `δu = (δv, δω)`（参照速度まわりの偏差）, `nu = 2`
- 連続系（参照軌道まわりの線形化）:
  - `ẋ_e =  w_r·y_e − δv`
  - `ẏ_e = −w_r·x_e + v_r·θ_e`
  - `θ̇_e = −δω`
- 1次オイラー離散化: `A = I + ts·A_c`, `B = ts·B_c`
- **A, B はホライズン内で一定**（`v_r, w_r` を現在値で固定）。Python 版も同じ扱い。

### 3.2 コスト

```
J = Σ_{k=0}^{N-1} [ zₖᵀQzₖ + reg(δuₖ) + ms·‖δuₖ − δu_{k−1}‖² ] + z_Nᵀ Q_f z_N
```

- `reg(δu) = δuᵀRδu`（L2） または `λ‖δu‖₁`（L1, Maximum Hands-off）
- `ms = move_suppress`。`k = 0` の `δu_{−1}` は**前ステップに実適用した δu**
- 既定値: `N=15, ts=0.1, Q=diag(10,10,1), R=diag(1,1), Q_f=10·Q`,
  `v_max=0.15, w_max=2.0`, 採用レンジ `λ=0.25〜2`, `move_suppress=2.0`

### 3.3 制約

- 力学: `z_{k+1} = A zₖ + B δuₖ`, `z₀` は固定
- 入力 box（実速度に課す）: `|u_nom + δuₖ| ≤ u_max`（要素ごと）,
  `u_nom = (v_r, w_r)`, `u_max = (v_max, w_max)`

## 4. ソルバ設計

### 4.1 Condensing（状態の消去）

`U = [δu₀; δu₁; …; δu_{N−1}] ∈ R^{2N}` を唯一の決定変数にする。

```
zₖ = A^k z₀ + Σ_{j=0}^{k−1} A^{k−1−j} B δu_j
```

を積み上げて `Z = Φ z₀ + Γ U` を得る。A, B が時不変なので `Γ` はブロック下三角
Toeplitz になり、`A^i B` を `i = 0…N−1` について一度作れば使い回せる。

平滑部は `U` の二次形式に落ちる:

```
f(U) = Uᵀ P U + 2 qᵀ U + const
P = ΓᵀQ̃Γ + R̃ + ms·DᵀD      （L1 の場合 R̃ = 0）
q = ΓᵀQ̃Φz₀ − ms·Dᵀd_prev
```

`Q̃ = blkdiag(0, Q, …, Q, Q_f)`（`z₀` の項は定数なので 0 でよい）、
`D` は差分作用素、`d_prev` は `δu_{−1}` を第0ブロックに置いたベクトル。

**採用理由**: 変数が `2N` 次元（N=15 で 30）に収まるため、KKT 行列の LDLᵀ 分解が
不要になる。分解が不要なら固定長配列だけで完結し、`malloc` ゼロが無理なく成立する。

**トレードオフ**: `Γ` が密になるため メモリ・演算とも O(N²)。`N ≤ 50` 程度なら
実用上問題ないが、Tier C で N を大きく伸ばす場合は sparse 形式（ADMM）に
劣る。この制約は README にも明記する。

### 4.2 近接勾配法（FISTA）

非平滑部は L1 と box の和で、どちらも成分ごとに分離する:

```
g(U) = λ‖U‖₁ + ι_box(U)
box: −u_max − u_nom ≤ δuₖ ≤ u_max − u_nom
```

成分ごとのプロクシマル作用素は、「ソフトしきい値 → 区間へのクリップ」の合成で
**厳密に**書ける:

```
prox(x) = clip(soft_threshold(x, λ·step), lo, hi)
```

根拠は「1次元の凸関数を区間上で最小化した解は、無制約の最小点を区間にクリップした
ものに等しい」こと。`0.5(u−x)² + λ|u|` は凸で、その無制約最小点が
`soft_threshold(x, λ)` である。したがって区間が 0 を含むかどうかは**関係ない**
（例えば `lo > 0` の区間では `|u| = u` なので最小点は `x − λ` になり、
`soft` を通した値のクリップと一致する）。総当たりでも確認済み。

必要な前提は `lo ≤ hi`（区間が空でない）のみで、これは `u_max > 0` から自動的に
満たされる。念のため `mpc_command` は空区間を検出したらエラーを返す。

- ステップ幅: `1/L`, `L = 2·λ_max(P)`。`λ_max` はべき乗法（固定20回）で推定
- 加速: FISTA の運動量 ＋ 単調性が崩れたときの再起動
- 停止: **反復回数固定**（既定200回）を第一とし、相対変化が閾値を下回れば早期終了。
  ベンチの再現性のため、固定回数モードを CLI で選べるようにする
- ウォームスタート: 前ステップ解を1つシフトして初期値にする（末尾は複製）

### 4.3 L2 の扱い

`λ = 0`、`R̃ = diag(R)` とすれば同じソルバがそのまま L2-MPC になる（非平滑部は
box のみ）。**L1/L2 で別実装を持たない**ことで、比較の公平性を保つ。

## 5. モジュール構成

各ファイルは単一の責務を持ち、ヘッダのみを介して結合する。

| ファイル | 責務 | 依存 |
|---|---|---|
| `src/linalg.[ch]` | 固定長の行列・ベクトル演算（積・転置・軸ごとの演算） | なし |
| `src/model.[ch]` | 誤差ダイナミクス `A,B` 構築、差動二輪の非線形プラント1ステップ | linalg |
| `src/path.[ch]` | 折れ線への射影・lookahead 参照姿勢・Kanayama 誤差・ゴール判定・減速 | なし |
| `src/condense.[ch]` | `Φ, Γ, P, q` の構築 | linalg, model |
| `src/prox.[ch]` | ソフトしきい値、box 射影、`prox` 合成 | なし |
| `src/fista.[ch]` | 近接勾配ソルバ本体（P, q, box, λ を受けて U を返す） | linalg, prox |
| `src/mpc.[ch]` | コントローラ。`mpc_command(z0, v_r, w_r) → (v, ω)` | 上記すべて |
| `src/sim.[ch]` | 閉ループsim（遅延リングバッファ・測定ノイズ・指標集計） | model, path, mpc |
| `src/main.c` | CLI 引数、CSV 出力 | sim |

`src/path.c` は `rover/follower_core.py` の、`src/sim.c` は `rover/sim_delay_probe.py`
の移植にあたる。

### 5.1 メモリ方針

- **動的確保を一切行わない**。すべて `config.h` のコンパイル時定数による静的配列
  - `MPC_N_MAX`（既定 30）, `MPC_NX 3`, `MPC_NU 2`, `PATH_WP_MAX`（既定 16）,
    `SIM_DELAY_MAX`（既定 8）
- 実行時の `N` は `MPC_N_MAX` 以下であることを初期化時に検証し、超過はエラー
- この方針は**テストで機械的に強制する**:
  `grep -rnE '\b(malloc|calloc|realloc|free)\s*\(' src/` が空であること

## 6. 検証

### 6.1 Python 版との数値一致

`rover/mpc_core.py` を真値とする。

1. Python 側で条件グリッドを回し、入力と結果を CSV に書き出す
   - `z₀` を格子状に振る（横偏差 ±0.3m、角度偏差 ±45°など）
   - `v_r ∈ {0.05, 0.1, 0.15}`, `w_r ∈ {−0.5, 0, 0.5}`
   - `reg ∈ {l2, l1}`, `λ ∈ {0.25, 1.0, 2.0}`, `move_suppress ∈ {0, 2.0}`
2. C 側は同じ入力 CSV を読み、自分の解を出力
3. 突き合わせる

**比較の主軸は目的関数値**にする。L1 解は非一意になったり平坦な谷を持つことが
あり、解ベクトルの直接比較は脆いため。判定は

- 目的関数値の相対差 `≤ 1e-4`（必須）
- 実際に適用される `δu₀` の絶対差 `≤ 1e-3`（参考。超過時は警告に留め、
  目的関数値が一致していれば合格とする）

### 6.2 閉ループの回帰テスト

`rover/test_mpc_sim.py` と同じ5ケース（直線2m×3、L字×2）で、C 版が全ケース到達し、
横偏差 RMSE が Python 版から大きく乖離しないこと（相対 20% 以内）。

### 6.3 卒研の主張の再現

`rover/sim_delay_probe.py` と同条件（L字、入力遅延2ステップ ≈ 200ms）で:

- **L1 + `move_suppress=0`**: ω の符号反転が多発（チャタリング）
- **L1 + `move_suppress=2.0`**: 符号反転が大きく減少
- **L2**: 遅延に対して頑健

を C 版でも観測し、テストとして固定する。これが本サンプルの見せ場になる。

### 6.4 単体テスト

外部フレームワークを使わない簡易ハーネス（`tests/` に main を持つ実行ファイル群、
`make test` で全実行）。対象:

- `path`: 射影・lookahead・ゴール判定の既知ケース
- `prox`: ソフトしきい値と box 射影の境界値
- `condense`: 小さい N で `Φ, Γ` を素朴な逐次計算と突き合わせ
- `fista`: 解析解が既知の小問題（box なし L2、box ありの1次元 L1）に収束すること

## 7. ビルド

- `make` — `-std=c99 -Wall -Wextra -Werror -pedantic -O2`、外部依存ゼロ
- `make test` — 単体テスト＋回帰テスト
- `make sanitize` — `-fsanitize=address,undefined` でテスト再実行
- 対応環境: Linux / macOS の gcc・clang。Windows は対象外

## 9. Tier C（後日、論文向け）への拡張点

本設計は次を**純粋な追加**として載せられる形にしておく。実装はスコープ外。

- `bench` ターゲット: N を振って求解時間の p50/p95/max を出す
- 同条件での Python(cvxpy+OSQP) との比較スクリプト
- 実機（RPi 復旧後）での再測定 → 「N≤30」の見直し

そのために、`mpc.h` は「1回の求解」を外から時間計測できる粒度で公開し、
ソルバの反復回数を固定できるようにしておく（4.2 の固定回数モード）。
