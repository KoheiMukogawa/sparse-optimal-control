# 全自動バッチ（走行→カメラ真値→自動原点復帰）運用手順

設計: specs/2026-07-16-camera-truth-pipeline-design.md（Phase 2+3）

## 前提（1回だけ）
1. カメラキャリブ（K/dist）が configs/camera_truth.yaml に記入済み
   （手順: docs/作業記録/カメラ真値_精度検証手順.md。床タグ座標は毎セッション自動化された）
2. usbipd で C270 を WSL に接続（管理者PowerShell）:
   `usbipd list` → `usbipd bind --busid <ID>` → `usbipd attach --wsl --busid <ID>`
   → WSLで `/dev/video0` を確認（PC再起動・抜き差し後は attach をやり直す）
3. RPi へ配置: `scp rover/udp_twist_bridge.py <rpi>:~/sparse_control/rover/`
4. 印刷黒枠の実測値を configs/camera_truth.yaml の floor_tag_size_m に記入
   （定規で1回。±0.5mm→1.2m先で4mm。同一印刷ロットなら共通）

## 毎セッション
1. RPi: nav_base 起動（**1つだけ**。多重起動するとモータ指令が競合する）
   `ros2 launch lightrover_ros nav_base.launch.py`
2. RPi: ブリッジ起動（起動しっぱなしでよい。sender の seq は時刻ベース初期化
   なので laptop 側の再起動で巻き戻らない＝2026-07-17修正済み）
   `source /opt/ros/humble/setup.bash && python3 ~/sparse_control/rover/udp_twist_bridge.py`
3. 床タグ4枚を前回の写真とだいたい同じ配置で置く（コース南側に tag0・tag3、
   北側に tag1・tag2。**メジャー・テープ不要**）→ サーベイ:
   `uv run python rover/survey_tags.py`
   （残差とタグ座標を表示して yaml を自動更新。コースを囲めていない・4枚が
   一直線・残差過大はエラーで教えてくれる → タグを置き直して再実行）
4. ロボットをカメラに写る適当な場所に置く（homing が原点へ自動搬送する。
   原点はタグが定義: tag0 中心の 20cm コース側）
5. laptop:
   `uv run python rover/run_batch.py configs/batch_<name>.yaml --backend real --auto --outdir results/<日付>_<name>`
   - 開始時に一括許可 [y/N]（全走行数が表示される）
   - 以後は全自動: 走行 → truth_*.csv 保存 → 原点復帰 → 次走行

## 安全（必ず有人監視）
- **q + Enter で即停止**（走行中は現走行のkill、復帰中は零速度送信）
- ブリッジ watchdog: UDP 0.5s 途絶で自動停止（WiFi断・laptopクラッシュ対策）
- 復帰中の安全停止: pose途絶1s / コース外接矩形+30cm逸脱 / 30sタイムアウト
- 復帰失敗はリトライ1回 → それでも失敗なら停止して人に Enter を求める
- 連続2本の走行失敗でループ自動停止

## 出力
- runs.csv に truth_end_x/y/theta・truth_end_dist_cm・truth_end_dist_abs_cm・
  truth_rmse_cm 列が追加
- **truth_end_dist_cm / truth_rmse_cm は「実測開始poseに固定したコース」基準**
  （純粋な追従性能。homing の向き残差±2°が混入しない）。
  truth_end_dist_abs_cm はタグ座標系ゴールへの絶対距離（設営・homing品質の指標）
- 走行ごとの真値時系列: results/<dir>/truth_<cond>_r<rep>.csv

## 実機で判明した注意（2026-07-17 E2E）
- ロボット上面タグの貼り角は `yaw_offset_rad` に要校正（直進40cmの弦方向 vs
  タグθ平均の差。今回+4.1°）。タグを貼り直したら再校正
- コマンドをターミナルへ貼るときは**改行なしの1行で**（折り返し表示は無害）
- 「原点復帰だけ」は `uv run python rover/run_batch.py configs/batch_<name>.yaml
  --backend real --home-only`（走行なし・許可プロンプト→復帰1回→終了）

## トラブルシュート（2026-07-17 実機セットアップで実証済み）
- **usbipd attach が「no WSL 2 distribution running」** → 管理者PowerShellは別ユーザー
  コンテキストでWSLが見えない。bind だけ管理者で行い、**attach は普通のPowerShell**で
- **/dev/video0 が Permission denied** → `sudo usermod -aG video $USER`（恒久・要再ログイン）。
  即時は `sudo chmod 666 /dev/video0 /dev/video1`
- **カメラは開けるが select() timeout でフレームが来ない** → USB/IP の等時転送帯域問題。
  `sudo modprobe -r uvcvideo && sudo modprobe uvcvideo quirks=128 nodrop=1 timeout=5000`
  で解消（実測: MJPG 1280x720 17fps）。恒久化:
  `echo 'options uvcvideo quirks=128 nodrop=1 timeout=5000' | sudo tee /etc/modprobe.d/uvcvideo.conf`
  ※ modprobe 後は /dev/video* が作り直されるので chmod もやり直す

## トラブルシュート（最終レビューのsim追試より）
- **truth_*.csv がデータ行ゼロ** → usbipd attach が剥がれた疑い（カメラ死は
  現状この形でしか表面化しない）。`ls /dev/video0` → re-attach
- homing が30sタイムアウトを繰り返す → 実機の加減速で余裕≈3秒しかない場合が
  ある。auto_batch 呼び出しの timeout_s を45に上げる（リトライは途中位置から
  継続するので単発timeoutは放置でよい）
- WiFi混雑時に復帰が「一瞬止まって再開」とカクつくのは watchdog の正常動作
  （10Hz送信 vs 0.5s watchdog＝連続5パケット喪失まで許容。loss10% simでも収束確認済み）
- カメラ遅延が大きいと最終向きが±10°程度残ることがある（sim: 遅延0.3sで最大12.7°）。
  CameraSource は MJPG＋バッファ1指定済みだが、E2E時に実fpsを一度確認する

## 初回実機E2E（未実施・ユーザー同席で順に）
0. サーベイ初回検証: floor_tag_size_m を定規実測 → `survey_tags.py` 実行 →
   測りやすい既知点2点（タグ位置など）にロボットを静置し、表示poseと実測の
   一致（±1〜2cm）を確認。ついでにカメラ実fpsも見る
1. ブリッジ疎通: ブリッジ起動 → laptopから零速度送信 → ブリッジログに受信表示
2. homing単体: ロボットをゴール付近に手置き → 原点±3cm/±5°に戻るのを監視
   （NEAR_R=10cm圏の前後進切替のチャタ有無・カメラ実fpsもここで確認）
3. `--auto` で l2×2本の短ループ → 12本フルバッチ（再開は `--auto --resume`、
   条件を絞るなら `--only <名前>` が auto でも効く）
