# 自立走行（空転）テスト 作業報告書

**作業日: 2026年6月12日**
**ブランチ: exp/autonomous-drive**

---

## 概要

公式サンプル `vstoneofficial/lightrover_ros2` を土台に、Kanayama制御則による
経路追従ノードを実装し、実機LiteRover（ジャッキアップ・車輪空転状態）で
直線2mとL字経路の自立走行を確認した。SLAM・AMCL・DDS（ラップトップ↔RPi通信）は
使わず、**/odomのみ・RPi完結構成**で自立走行の最小構成を成立させた。

## 1. 公式サンプルの調査結果

`vstoneofficial/lightrover_ros2`（Humble対応）を調査し、以下が判明:

| 項目 | 内容 |
|------|------|
| 速度指令トピック | **`rover_twist`**（`/cmd_vel` ではない。Nav2用launchでremapしている） |
| オドメトリ | `odom_manager` が `/odom`（約30Hz）とTF（odom→base_footprint）を配信 |
| 車輪制御 | `pos_controller` が rover_twist を受け、I2C経由で車輪レベルのP制御 |
| 速度レンジ | ゲームパッド基準で並進 0.1 m/s、旋回 2.0 rad/s |
| 自立走行用launch | `nav_base.launch.py`（i2c + odom + pos_controller + LiDAR、gamepadなし） |

**結論: モータ制御・オドメトリはサンプル流用で済み、自作は経路追従ノード1個のみ。**

注意: `pos_joycon.launch.py` はgamepadノードが rover_twist を配信するため、
自立走行ノードと指令が競合する。自立走行時は `nav_base.launch.py` を使うこと。

## 2. 実装

### 構成

```
rover/
  follower_core.py      # 経路射影・Kanayama誤差・制御則（ROS非依存）
  path_follower.py      # ROS2ノード: /odom購読 → rover_twist配信
  test_follower_sim.py  # 運動学モデルでのクローズドループ検証
configs/
  path_straight_2m.yaml # 直線2m
  path_L_turn.yaml      # 直線1.5m + 左90度 + 直線1.5m
```

純粋ロジック（follower_core）とROSノードを分離したのは、
後でKanayama制御則をL1スパースMPCに差し替える際、
同じ経路射影・誤差計算を流用するため。

### 制御則（Kanayama）

参照姿勢は経路（折れ線）への射影点から lookahead = 0.15m 先に置く。
誤差（ロボット座標系）(x_e, y_e, θ_e) に対し:

- v = v_r cosθ_e + K_x x_e
- ω = ω_r + v_r (K_y y_e + K_θ sinθ_e)、直線経路なので ω_r = 0

ゲイン: K_x=0.5, K_y=5.0, K_θ=3.0（シミュレーションで決定、実走行で要再調整）
制限: v_r=0.1 m/s, |v|≤0.15 m/s, |ω|≤2.0 rad/s（ゲームパッドのレンジに準拠）

### 安全機構

- odomが0.5秒途絶したら停止指令を配信
- ノード終了時（Ctrl+C含む）に必ず停止指令を配信

## 3. シミュレーション検証で発見・修正したバグ

実機投入前に運動学モデルでのクローズドループ検証を行い、2件のバグを修正:

1. **ゴール超過点での停滞**: ゴール手前で減速しないと、v_r cosθ_e と K_x x_e が
   釣り合う「ゴールの v_r/K_x = 20cm 先」が安定平衡点になり、到達判定圏
   （5cm）に入らないまま停止する。
   → ゴールから0.3m以内で基準速度を距離比例で減速する `goal_scaled_vr` を追加。
2. **横偏差残留時の未到達**: コーナーで横にふくらんだままゴール脇を通過すると、
   円形の到達判定（半径5cm）に入らない。
   → 最終セグメントに垂直な「ゴール線」の通過判定 `goal_crossed` を追加。
   経路追従実験では走り切りが重要で、最終姿勢のズレはRMSE側で評価するため
   この判定が適切。

修正後のシミュレーション結果（20Hz、初期ズレ各種）:

| ケース | 結果 | 所要時間 | 横偏差RMSE |
|--------|------|---------|-----------|
| 直線2m（経路上スタート） | 到達 | 13.7s | 0.0cm |
| 直線2m（横20cm・30度ズレ） | 到達 | 14.2s | 16.9cm |
| 直線2m（横-30cm・-45度ズレ） | 到達 | 14.4s | 23.0cm |
| L字（経路上スタート） | 到達 | 22.8s | 11.6cm |
| L字（横15cmズレ） | 到達 | 22.8s | 12.6cm |

## 4. 実機環境の修正（transforms3d非互換）

`nav_base.launch.py` 起動時に odom_manager が即死する問題が発生。

- 原因: apt版 transforms3d 0.3.1（`/usr/lib/python3/dist-packages`）が `np.float` を
  使用しており、ユーザーローカルの新しい numpy 1.26.4 と非互換
  （`AttributeError: module 'numpy' has no attribute 'float'`）
- 対処: `pip install --user --upgrade transforms3d` → 0.4.2 がユーザーローカルに
  入り、apt版をシャドウして解決（sudo不要・apt環境は不変更）

## 5. 実機（空転）テスト結果

ジャッキアップ状態で車輪を空転させ、エンコーダオドメトリ上での走行を確認。

| テスト | 結果 | 所要時間 | 最終位置（odom） |
|--------|------|---------|-----------------|
| 直線2m | 目標到達・自動停止 | **13.8s**（シム予測13.7s） | x=1.957m, y=0.0002m |
| L字 | 目標到達・自動停止 | **17.4s** | x=1.550m, y=1.502m |

- 直線はシミュレーション予測とほぼ一致（負荷なしのため当然ではある）
- L字は前回走行のodomが残っており横0.46mズレからのスタートになったが、
  経路に復帰して完走（大初期誤差からの復帰テストを兼ねた）
- **odomはノード再起動までリセットされない**ことが判明。連続テスト時は
  odom_manager を再起動するか、経路を現在位置基準で生成する必要がある

# 端末1: ベースノード
ros2 launch lightrover_ros nav_base.launch.py
# 端末2: 経路追従

python3 path_follower.py --ros-args \
  -p path_file:=/home/mukougawakouhei/sparse_control/configs/path_straight_2m.yaml
