# 発表スライドのデザイン方針 —— 「AIっぽさ」を消す

卒論発表（および以降の研究会）のスライドを作るときの確定ルール。
**目的は装飾を上手くすることではなく、研究発表として普通に見えること。**

## 1. 「AIっぽさ」は3層ある

直し方を間違えないために分けて考える。10/22 のデッキ（`研究会発表_2026-10-22.pptx`）を
実測した値を併記する。**装飾を剥がしても2層目・3層目が残るので「まだAIっぽい」となる。**

### 第1層: 視覚（剥がせば消える）

| 要素 | 10/22 デッキ | 出典 |
|---|---|---|
| 角丸カード | 32個 | A・D |
| 擬似ドロップシャドウ（カード背面に淡色の面） | 25個 | D |
| 情報を持たない飾りバー | 42個 | A（ノイズ）・D（意味のないカラーバー） |
| 色帯・全面の色塗り | 21個 | A（余白を埋める衝動） |
| タブ（上角だけ丸い見出し形） | 3個 | D |
| 色数 | 23色 | A（4色に）・D（3色に） |

→ `restyle_pptx.py --plain` で機械的に除去済み。**ここだけでは足りない。**

### 第2層: 言語（記号と言い回し）

同じ内容でも、記号の選び方と言い回しで「生成物」に見える。10/22 デッキの実測:

| 記号・定型 | 回数 | なぜ目立つか |
|---|---|---|
| `→` | 48 | 文章の中で論理をすべて矢印で済ませている |
| `●`（中黒の大きい丸） | 45 | 研究発表の箇条書きは小さい `・` か無印。`●` は配布資料の記号 |
| `／`（全角スラッシュ） | 34 | 「THEORY ／ 論文解説」のような区切り。日本語の研究発表では使わない |
| `＝`（全角イコール） | 23 | 「経路追従制御＝あらかじめ決めた経路を…」のような言い換え癖 |
| `―` / `–`（ダッシュ） | 32 | **見出しの中のダッシュは AI 文章の代表的な特徴**（出典D） |
| 英語の章ラベル `THEORY` `PROGRESS` `APPENDIX` | 4 | 日本語の発表に英語の飾り見出しが入るのはコンサル資料の語彙 |
| 連番ラベル「論文解説 01」「取り組み 11」 | 20 | 全枚に同じ型の札が付く＝テンプレ感 |
| 定型の小見出し「やったこと」「分かったこと」「なぜ必要か」 | 7 | 枚ごとに考えず、同じ骨格に流し込んだように見える |

### 第3層: 構造（いちばん効く）

- **すべてのスライドが同じ重みで並んでいる。** 出典Dが挙げる最大の特徴がこれ。
  10/22 デッキは平均 359 字・中央値 368 字で、**36枚がほぼ同じ密度**。
  本当に見せたい1枚（対策前後の比較）も、補足の1枚も、同じ見た目になっている。
- **見出しが体言止めの名詞句**（「計算負荷 ― 疎にする代償と、遅延への回り込み」）。
  出典Bの研究では、見出しを**主張の文**にしたほうが聴衆の理解と記憶が有意に良い
  （Garner & Alley 2013, p < .01）。名詞句の見出しは「何が言えるのか」を聴衆に預けてしまう。
- **図が主役になっていない。** 36枚中、図を貼ってあるのは12枚。残りは文字が主役。

## 2. 到達目標は自分の 8 月のデッキ（出典E）

`院試発表_向川航平(0816).pdf` を解析した。**これは研究発表として普通に見える。**
10/22 のデッキはここから外れた。仕様を抜き出すと次のとおり。

| | 院試デッキ（目標） | 10/22 デッキ |
|---|---|---|
| フォント | **BIZ UDPGothic / BIZ UDPGothic Bold**（和欧とも）＋数式 Cambria Math ＋コード Courier New | Meiryo（和欧とも）＋コード MS Gothic |
| 色 | **無彩色＋朱1色だけ**。本文 `#2D2D2D`／見出し `#1A1A1A`／注記 `#757575`／罫線 `#C4C4C4`・`#D7D7D7`／下地 `#F4F4F4`／**強調 `#B1390A`** | 23色 |
| 見出し | 30 pt 太字・左揃え。上に小さな灰色のラベル（「【1】これまでの研究活動・学習内容」「補足 D」） | 26 pt ＋ ティールの連番ラベル |
| 本文 | 12〜14 pt。**箇条書きは `・` で3項目まで**、行間広め | 12.5 pt ●で5〜8項目 |
| 囲み | **1枚に最大1つ**。枠線だけ（塗りなし）の薄い箱に、数値か「問い」を1行 | カード・帯・タブが1枚に4〜8個 |
| 図形 | 角丸なし・影なし・矢印は必要な所だけ | 角丸32・擬似影25・飾り42 |
| 主役 | **表と図**。表は横罫だけ、強調する行だけ朱 | 文字 |
| ページ番号 | なし | 全枚に手打ち |

> **文字サイズは差ではなかった。** 院試デッキの本文も 12〜14 pt で、10/22 の 12.5 pt と同じ。
> 違うのは**見出しとの比（30 pt : 13 pt ＝ 2.3倍）と、1枚の語数**。
> 前の版で書いた「本文 18 pt 下限」は**大きな会場で投影する場合の学会の目安**（出典C）であって、
> AIっぽさの原因ではない。会場が決まったら上げる。

## 3. 確定ルール

### タイポグラフィ

| 用途 | フォント | サイズ |
|---|---|---|
| 見出し | BIZ UDPGothic Bold | 30 pt |
| 章ラベル（見出しの上） | BIZ UDPGothic | 11〜12 pt・`#757575` |
| 本文 | BIZ UDPGothic | 13〜14 pt（会場で投影するなら 18 pt 以上） |
| 注記 | BIZ UDPGothic | 10〜11 pt・`#757575` |
| 数式 | Cambria Math | 本文と同じ |
| コード | **MS Gothic**（和文等幅。日本語コメントと ASCII の桁を揃えるため） | 14 pt 下限 |

- 和文はゴシック（出典A・C）。**BIZ UDPGothic は和欧ともこれ1本でよい**
  （欧文も専用設計されているので、出典Aの「欧文に和文フォントを使うな」には触れない）。
  前の版の「Meiryo＋Segoe UI」は**この指定で置き換える**。自分の既存デッキと揃うほうが強い。
- 見出しと本文のサイズ比を **2.3倍以上**。ここが情報の重みの差になる。

### 色（無彩色＋1色）

```
本文 #2D2D2D ／ 見出し #1A1A1A ／ 注記・ラベル #757575
罫線 #C4C4C4 ／ 下地 #F4F4F4 ／ 背景 #FFFFFF ／ 強調 #B1390A
```

- **文字に使う有彩色は朱 `#B1390A` の1色だけ。** 2色目を足したくなったら太字で済ませる。
- **図の中の色は別系統**（`rover/fig_style.py` の Okabe-Ito 4色）。
  スライドの地の色と図の系列色を混ぜない。図の中だけが色を持つ状態にする。
- 背景は白。図の背景（matplotlib の白）と一致させて「貼り付け感」を消す（出典A）。

### 図形

出てよいのは**図・表・数式・結論1行・細い罫線**だけ。

- 角丸・影・グラデーション・タブ・色帯・飾りバーは**使わない**
- 囲みは1枚に最大1つ、枠線 `#C4C4C4` だけ（塗りなし）
- 矢印は**意味がある所だけ**（構成図の流れ・因果）。文章の中で `→` を多用しない
- 表は横罫だけ。見出し行は無彩色、強調したい行だけ朱

### 言語

- 見出しは**言い切りの文**にする（出典B）。
  × 「計算負荷 ― 疎にする代償と、遅延への回り込み」
  ○ 「求解時間は 0.1 秒以内に収まっている」
  - ただし全枚に図を用意する必要はない（出典B' の批判）。表でも数値1つでもよい
- **見出しにダッシュ（`―` `–`）を使わない。** 使うなら読点か改行
- 箇条書きは `・`、**3項目まで**。`●` は使わない
- `／` と `＝` を区切り記号として使わない
- 章ラベルを英語にしない（`THEORY` → 「1. 論文解説」）
- 「やったこと」「分かったこと」のような**定型の枠を全枚に置かない**

### 構成（重みを変える）

- **1枚1メッセージ。** 本文は 150 字以内を目安（10/22 は平均 359 字）
- **作る前に、全枚の「このスライドで言いたいこと」を1文ずつ書き出す**（2026-11-26 追加）。
  枚を先に並べてから中身を埋めると、意図のない「定型の枠」が増える。
  手順は次の3段で固定する:
  1. **意図の一覧を作る**（枚数ぶんの1文。これが実質の台本になる）
  2. 本文・図は**その1文を支える材料だけ**を置く。支えないものは削るか口頭へ回す
  3. 見出しはその1文を使うのが既定。ただし**前面に出すかは別問題**（下記）
  → **意図を1文で書けないスライドは作らない。** 削るか、隣の枚に統合する

- **「意図を決める」と「意図を前面に出す」は分ける**（2026-11-26 追加）。
  意図は**全枚で必ず決める**が、それを強く見せるかはスライドの種類で変える。
  - 結論・主張の枚 → 意図をそのまま言い切りの見出しにする（出典B）
  - **データの枚（グラフ・数値比較）→ 見出しは静かな事実文でよい。**
    「〜が優れている」と大書きせず、**図が自分で語るように作る**。
    主張はノートと口頭に置く。装飾（強調色・吹き出し・囲みの多用）で
    結論を押し出すことはしない
  → 聴衆に読ませるのは**図とその1本の軸**であって、こちらの結論の宣言ではない

- **1スライド1情報。** データの枚はとくにこれを守る（2026-11-26 追加）。
  「1枚1メッセージ」は語数の話だが、こちらは**載せる情報の数**の話である。
  | | 上限 |
  |---|---|
  | 図・表 | **1枚に1つ** |
  | 比較する軸 | **1つ**（条件×指標を同じ枚に広げない） |
  | 読ませる数値 | **3つまで**（それ以上は表ではなく口頭・付録へ） |
  指標が4つあるなら**4枚に割る**。条件が4つで指標が5つある表をそのまま貼ると、
  聴衆はどこを見ればよいか分からず、結果として何も伝わらない。
  **卒論の表をそのまま貼らない**（本文の表は読む速度が前提の密度で作ってある）
- 全枚を同じ密度にしない。**山になる2〜3枚は図を大きく・文字を少なく**し、
  補足は密度を上げてよい。密度の差がそのまま「どこが大事か」になる
- 配分は 背景・目的を 1/3 以下、結果〜結論を 1/3 以上（出典C）
- **ページ番号は入れる。** 質疑でページを指定されるため（出典C・筑波大）。
  出典Aは「入れない」を勧めるが、**学会・審査の場では入れる側を採る**。
  ただし手打ちせず、挿入→スライド番号のフィールドにして自動更新させる
  （前の版で「入れない」としたのを**ここで訂正する**）

## 4. 10/22 デッキを直す順序

| | やること | 手段 |
|---|---|---|
| 1 | フォントを BIZ UDPGothic に、色を無彩色＋朱1色に、`●`→`・` | `restyle_pptx.py --plain`（機械） |
| 2 | 装飾（角丸・擬似影・飾りバー・色帯・タブ）を除去 | 同上（機械） |
| 3 | **全枚の意図を1文ずつ書き出し、それを見出しにする**（36枚） | 手作業・いちばん効く |
| 4 | 見出しのダッシュ・英語ラベル・連番ラベルを外す | 手作業 |
| 5 | 文字を削る（平均 359 字 → 150 字）。削った分は口頭とノートへ | 手作業 |
| 6 | 山の2〜3枚を図中心に組み直す。残りは密度を落とす | 手作業 |
| 7 | ページ番号をフィールドで入れ直す | 手作業 |
| 8 | PowerPoint で全枚を目視（WSL 側では描画できない） | 手作業 |
