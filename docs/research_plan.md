# 研究計画（2026-06-12策定）

卒業研究「農業用ロボットの経路追従制御におけるスパース最適制御（Maximum Hands-off Control）」のフェーズ別計画。

## 前提

- 中間発表: 2026年9〜10月
- 卒論提出: 2027年2月、最終発表: 提出後
- 実機（LiteRover）実験まで必須
- 比較軸: L1スパースMPC vs 通常のL2-MPC
- 評価指標: RMSE / 消費エネルギー / 入力スパース性（ゼロ入力率） / 計算負荷（求解時間）

|---------|------|--------|

## P1: スパースMPCシミュレーション（6/15〜7/15）

オープンループ（`docs/作業記録/sparse_rover.py`）をクローズドループMPCに拡張する。
ブランチ: `exp/sparse-mpc`

### タスク

1. **リポジトリ整備**（〜6/20）
   - `src/`（モジュール本体）、`configs/`（実験条件YAML）、`results/` のディレクトリ構成を作る
   - uvでcvxpy / numpy / matplotlib / pyyamlを管理（`pyproject.toml`）
   - sparse_rover.pyの内容を「プラントモデル」「最適化」「可視化」に分割
2. **非線形シミュレータ**（〜6/25)
   - 差動二輪の非線形運動学でプラントを実装（制御は線形化モデル、プラントは非線形で分離）
   - 外乱（横すべり・入力ノイズ）とモデル化誤差を注入できるようにする
3. **Kanayama誤差モデル**（〜6/30）
   - 参照経路（直線・円弧・ウェイポイント列）と現在姿勢から誤差状態 (x_e, y_e, θ_e) を計算
   - 後の ROS2 ノード（P3）と同一のロジックをPython関数として実装し共用する
4. **L1-MPC実装**（〜7/8）
   - ローリングホライズン化: 毎ステップ `min ||u||_1 + 終端コスト s.t. ダイナミクス, |u|≤u_max` を解き、先頭入力のみ適用
   - 終端等式制約は実行不可能になりやすいので、終端コスト（またはソフト制約）方式も実装して比較
   - L2-MPC（||u||_2^2 コスト）をベースラインとして同条件で実装
5. **評価パイプライン**（〜7/15）
   - 1回の実験 = YAML設定 → シミュレーション → `results/<日付_実験名>/` にメトリクス(JSON)と図を自動保存
   - 指標: 経路RMSE、Σ|u|（エネルギー代理）、ゼロ入力率、1ステップあたり求解時間

### 完了条件（マイルストーン M1）

- 外乱ありのクローズドループでL1-MPCが経路追従できる
- 同一条件でL1とL2の4指標が1コマンドで比較出力される

## P2: 比較実験・CasADi移行（7/15〜8/31）

### タスク

1. **パラメータスタディ**（〜7/31）
   - L1重みλのスイープ（スパース性 vs RMSEのトレードオフ曲線）
   - ホライズン長N、制御周期hのスイープ（計算負荷との関係）
   - 経路形状3種以上: 直線、円弧、圃場を模したヘッドランド旋回（直線往復＋180度旋回）
2. **CasADi + IPOPT移行**（〜8/15）
   - 非線形モデルを直接使うNMPC版を実装（線形化誤差の影響を評価）
   - L1項は補助変数による絶対値の線形化で扱う
   - cvxpy版との解の一致確認と求解時間比較（RPi4実装の実現可能性判断）
   - ※IPOPTが重い場合はOSQP/線形MPCに留める判断をここで行う
3. **結果まとめ**（〜8/31）
   - 中間発表用の主要図表（トレードオフ曲線、軌跡比較、入力時系列のスパース性比較）を確定

### 完了条件（M2）

- 「λを上げるとゼロ入力率がX%→Y%に上がり、RMSEはZ cm悪化する」と定量的に言える
- RPi4（制御周期0.1秒想定）で間に合うソルバ構成の目処が立つ

## P3: 実機基盤整備（6月〜8月、P1/P2と並行・週1〜2日）

シミュレーションの待ち時間や気分転換に並行で進める。
ブランチ: `exp/rover-setup`（ROS2側）

### タスク

1. **DDS通信の解決**（6月中）
   - WindowsファイアウォールのUDP 7400-7500開放を試す
   - 1週間で解決しなければ「SSH X11転送 + RPi上で完結」に方針固定して先へ進む（沼回避）
2. **SLAM地図作成・保存**（〜7月上旬）
   - teleopで走行して地図作成、`map_saver_cli` で保存
   - 実験場所（廊下・実験室）の地図を確保
3. **自己位置推定の確認**（〜7月下旬）
   - 保存地図 + AMCL（または当面 /odom のみ）で姿勢が取れることを確認
   - /odomのドリフト量を計測しておく（実験設計の根拠になる）
4. **Kanayama誤差計算ノード**（〜8月末）
   - P1-3で作ったPythonロジックをROS2ノード化（RPi側、Humble）
   - 入力: /odom（またはAMCL姿勢）+ 参照経路YAML、出力: 誤差トピック
   - teleop走行でログを取り、誤差計算が正しいことをrosbagで検証

### 完了条件（M3）

- 地図上で自己位置が取れ、参照経路に対する誤差がトピックとして流れている

## P5: 実機実装・実験（10月〜11月）

ブランチ: `exp/real-robot-mpc`

### タスク

1. **L1スパース制御ノード実装**（10月前半）
   - P2で確定したソルバ構成をROS2ノード化、/cmd_vel を出力
   - 計算が重い場合の代替案（優先順）: ①ラップトップ側で計算しDDSで送る ②ホライズン短縮 ③制御周期を0.2秒に緩和
2. **リアルタイム性検証**（10月中）
   - RPi4上での求解時間を計測、制御周期内に収まるか確認
   - 間に合わない場合は上記代替案に切り替え（11月に持ち越さない）
3. **実機比較実験**（10月下旬〜11月末）
   - 直線・旋回を含む参照経路でL1 vs L2を各条件複数回走行
   - rosbagで全データ記録、4指標をシミュレーションと同じパイプラインで算出
   - 消費エネルギーは入力ノルムの代理指標＋可能ならバッテリー電圧/電流ログ
   - シミュレーションと実機の差（モデル化誤差の影響）を考察材料として整理

### 完了条件（M5）

- 実機でL1とL2の比較データ（各経路×複数回）が揃い、再現可能な形で保存されている

## リスクと対策

| リスク | 影響 | 対策 |
|--------|------|------|
| DDS通信が解決しない | P3遅延 | 1週間で見切り、RPi完結構成に固定（解決済みの代替手段あり） |
| RPi4でMPCが制御周期に間に合わない | P5の根幹 | P2で事前に計算負荷を評価。オフボード計算（ラップトップ側）を第一代替に |
| 終端制約のMPCが実行不可能になる | P1停滞 | ソフト制約/終端コスト方式を最初から併設 |
| 実機実験のやり直し（11月までに不備発覚） | 卒論の質 | rosbagで生データを全保存し、指標は後から再計算可能にする |
| Surface Laptop Goのメモリ不足（IPOPTビルド等） | P2遅延 | pipバイナリ優先、重い処理はRPiかColabに逃がす |
