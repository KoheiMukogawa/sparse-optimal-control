## 1. 30秒サマリ

農業用の小型移動ロボットの経路追従制御に、**スパース最適制御（最大ハンズオフ制御、$L^1$ 正則化 MPC）** を適用した。
理論上は「必要なときだけ動かし、それ以外は完全に止める」入力が得られるはずだった。

ところが**実機に載せた瞬間、逆の現象が起きた**。コーナーで激しいチャタリング（角速度の符号反転18回、入力積算はベースラインの4.1倍）が発生し、**入力を疎にするはずの手法が4条件中で最も疎でない挙動を示した**。

原因は**実機の入力遅延（約200 ms）**であることを、遅延注入シミュレーションで定量的に再現して特定した（遅延2ステップで $\Sigma|u|=18.49$・反転19回 ⇔ 実機実測 19.17・18回）。
対策として**入力の「大きさ」ではなく「変化率」にペナルティを課す移動抑制項**を設計し、実機で**符号反転 18回→1回、$\Sigma|u|$ 19.17→5.02** へ改善しつつ、**ゼロ入力率 0.88 というスパース性は維持**した。

結論：**入力遅延への明示的な配慮が、スパース制御を実機で成立させる必須条件である。**

## 2. 研究の背景と問い

### 2.1 応用背景

農業分野の就業人口減少・高齢化により、圃場作業の自動化が求められている。
播種・除草・防除・収穫はいずれも「畝に沿って正確に進む」ことが前提であり、**経路追従の精度がそのまま作業品質を決める**。

対象は市販の小型移動ロボット **LiteRover（ヴィストン製）**。車載計算機は **Raspberry Pi 4**。
「**限られた計算資源で、実時間（10 Hz）で解く**」という制約が本研究を通じた主題になっている。

### 2.2 技術的な問題意識 —— 「入力の手数」

従来の経路追従制御（古典的な Kanayama 法、標準的な L2-MPC）は、**誤差がゼロでない限り何らかの入力を出し続ける**。
実測では Kanayama 法のゼロ入力率は $0.650$、すなわち**走行時間の 35 % にわたって操舵し続けている**（L2-MPC の 12.8 % の約 2.7 倍）。一方その操舵量自体は小さい（最大 $0.327$ rad/s）。
つまり**小さな入力を絶え間なく打ち続ける**のが従来手法の典型である。

これは実用上、次の不利をもたらす：
- アクチュエータの消耗（微小操舵の反復）
- 電力消費（屋外作業ロボットは電源が限られる）
- 外乱の励起（滑りやすい路面で細かな操舵が滑りを誘発しうる）

→ **必要なときにだけ大きく動かし、それ以外は完全に止めておけないか？**

## 3. 理論的枠組み —— 最大ハンズオフ制御

- 永原による **最大ハンズオフ制御（maximum hands-off control）**：入力の大きさを小さく抑えるのではなく、**入力がちょうどゼロである時間を最大化する**設計論。制御入力の $L^0$ ノルム（非ゼロである時間の長さ）の最小化として定式化される。
- $L^0$ 最小化は組合せ的で直接解けないが、**一定の条件（正規性条件）下で $L^1$ ノルム最小化と等価**になることが知られる。
- $L^1$ 最小化は**凸最適化**なので実装可能。その最適解は入力が上限・下限・ゼロのいずれかを取る **bang-off-bang 構造**を持つ。
- これは従来手法の「なめらかで常時ゼロでない入力」と**質的に異なる**。

**予備数値実験（本研究で独立に再実装・検証済み）**：開ループのスパース最適制御問題を解くと、$\delta\omega$ のゼロ数が **39/50 = 78 %**、$L^1$ ノルム 30.65、終端誤差 1e-14 オーダーで、既往の記録値を完全に再現した。

**副産物の理論的知見（発表で使える小ネタ）**：
同じ問題で $\delta v$（並進速度補正）側のゼロ数は 0/50 だった。これは入力行列 $B_d$ の構造上 $\delta v$ と $\delta\omega$ が完全に分離し、**$\delta v$ 側の部分問題が退化している**ため（終端制約が $\Sigma\delta v = -20$ の1本だけ → 同符号なら配り方によらず $L^1$ 値が同一＝最小解が無数に存在）。
つまり $\delta v$ のスパース性はソルバ依存であり問題の性質ではない。
→ **「スパース性を $\delta\omega$（操舵補正）で測る」という本研究の指標選択が、ここで数学的に正当化された。**

> 【要確認】第2.5節の定理（正規性条件の定義・定理の主張・定理番号）は原典で本人が確認すること。**口頭試問で最も問われやすい箇所。**

## 4. 提案手法の定式化

### 4.1 車両モデル

差動二輪型。姿勢 $(x,y,\theta)$、入力は並進速度 $v$・角速度 $\omega$：

$$\dot{x}=v\cos\theta,\quad \dot{y}=v\sin\theta,\quad \dot{\theta}=\omega$$

横方向へ直接移動できない**非ホロノミック系**。

| 諸元 | 値 |
|---|---|
| $v_{\max}$ | 0.15 m/s |
| $\omega_{\max}$ | 2.0 rad/s |
| 基準速度 $v_r$ | 0.1 m/s |
| 制御周期 $T_s$ | 0.1 s（10 Hz） |
| トレッド | 0.1514 m（車体側オドメトリ積算用） |

### 4.2 誤差ダイナミクス

Kanayama 誤差 $z=(x_e,y_e,\theta_e)^\top$、入力は参照速度からの**補正** $\delta u=(v-v_r,\ \omega-\omega_r)^\top$。参照軌道まわりで線形化すると

$$\dot{x}_e=\omega_r y_e-\delta v,\quad \dot{y}_e=-\omega_r x_e+v_r\theta_e,\quad \dot{\theta}_e=-\delta\omega$$

$$A_c=\begin{bmatrix}0&\omega_r&0\\-\omega_r&0&v_r\\0&0&0\end{bmatrix},\quad
B_c=\begin{bmatrix}-1&0\\0&0\\0&-1\end{bmatrix}$$

1次オイラー離散化：$A=I+T_sA_c,\ B=T_sB_c$。$A,B$ は $v_r,\omega_r$ に依存するため毎ステップ変化する（パラメータ化して問題構造は固定）。

### 4.3 ベースライン：L2-MPC

$$\min_{\delta u_0,\dots,\delta u_{N-1}}\ \sum_{k=0}^{N-1}\left(z_k^\top Q z_k+\delta u_k^\top R\,\delta u_k\right)+z_N^\top Q_f z_N$$

s.t. $z_0=z(t)$、$z_{k+1}=Az_k+B\delta u_k$、$|u_{\mathrm{nom}}+\delta u_k|\le u_{\max}$

重み：$Q=\mathrm{diag}(10,10,1)$、$R=\mathrm{diag}(1,1)$、$Q_f=10Q$、$N=15$。

**設計判断2点（質疑で効く）**：
1. 入力制約を補正 $\delta u$ ではなく**実速度** $u_{\mathrm{nom}}+\delta u$ に課している（制約すべきはモータが実際に出せる速度だから）。
2. 終端条件を等式制約でなく**ソフトコスト $Q_f$** にした。等式制約のままだと外乱で誤差が大きいとき実行不可能（infeasible）になり、実機では求解失敗＝停止を意味するため。到達性は $Q_f=10Q$ で担保。

### 4.4 L1 化 —— なぜ補正 $\delta u$ を penalize するのか（重要）

$$\min\ \sum_{k=0}^{N-1}\left(z_k^\top Q z_k+\lambda\|\delta u_k\|_1\right)+z_N^\top Q_f z_N$$

制約は L2 と完全に同一。**実装上の差は目的関数1行のみ**（`cp.quad_form` → `cp.norm1`）。これにより「同一骨格・同一制約で正則化のみを変えた比較」が成立する。

**原理論からの重要な変更**：最大ハンズオフ制御は入力 $u$ 自体を疎にする設計だが、経路追従では参照速度 $v_r \ne 0$ である。
$u$ 自体を疎にすると **$v=0$ の時間が最大化され、ロボットが走行そのものを止めてしまう**。
そこで**参照速度からの補正 $\delta u$ を疎にする**。$\delta u=0$ の区間は $u=u_{\mathrm{nom}}$、すなわち**参照速度のまま巡航している**状態になる。
→「補正を打つ瞬間だけ動かし、それ以外は参照どおり流す」という、経路追従において意味のあるハンズオフが得られる。

### 4.5 対策：移動抑制項（本研究の提案の核）

$$\Delta\delta u_k=\delta u_k-\delta u_{k-1},\qquad
\text{cost} \mathrel{+}= w_{ms}\sum_{k=0}^{N-1}\|\Delta\delta u_k\|_2^2$$

$k=0$ における $\delta u_{-1}$ には**前回の制御周期で実際に適用した補正**を用いる（ホライズン内部だけでなく制御周期をまたいだ連続性も評価される）。

**性質**：
- $w_{ms}=0$ で従来の L1 と完全一致 → **後方互換**
- 二次ペナルティで $L^1$ 項とは独立に働く → **スパース性の構造を壊さない**
- 抑制するのは**変化率**であって大きさではない → 「必要なときに大きく動かす」bang-off-bang の性格は保たれ、「短時間で符号を反転させる」挙動のみが抑えられる

### 4.6 設計パラメータ

| 記号 | 採用値 | 根拠 |
|---|---|---|
| $\lambda$ | 0.3 | 到達性だけなら 0.25〜2 が可（$\lambda\ge3$ で破綻）。しかし遅延を 0〜4 ステップ振ると $\lambda\ge1$ は追従性能が遅延に対して不安定 → **実用採用域は 0.25〜0.5** |
| $w_{ms}$ | 2.0 | 遅延2ステップ時点の性能では 0.5 でも同等。差は遅延を伸ばすと現れ、遅延4ステップで 0.5 は $\Sigma|u|=16.16$（反転9）とチャタへ逆戻り、2.0 は 7.52（反転4）に留まる → **2.0 が買っているのは「遅延マージン」** |
| $N$ | 15（設計上限 30） | RPi4 実測で $N\le30$ が 0.1 s 周期内。実走行では他ノード負荷で 1.3〜2.8 倍になるため余裕を見て 15 |

### 4.7 実装

cvxpy + **OSQP**。**DPP（disciplined parametrized programming）準拠**で記述し、$A,B,z_0,u_{\mathrm{nom}}$ をパラメータ宣言 → 問題構造のコンパイルは初回のみ、毎周期は係数差し替えと再求解だけ。warm start 有効。これにより RPi4 上で 0.1 s 周期を満たす。

言語 Python（uv 管理）。開発機 WSL2 Ubuntu 24.04 / ROS 2 Jazzy、実機 Ubuntu 22.04 / ROS 2 Humble。

> 【注記】当初の実装計画には CasADi + IPOPT による非線形 MPC も含まれていたが、本研究では cvxpy + OSQP による凸定式化のみを実施した。発表で「範囲」として明示するか要判断。

### 4.8 安全機構（3つ、いずれも零速度指令で停止）

1. **オドメトリ途絶** —— 最後の `odom` 受信から 0.5 s 以上経過
2. **求解失敗** —— ソルバがエラー／解が得られない
3. **ゴール到達** —— 終点まで 0.05 m 未満、または通過判定

加えて、出力直前に $v_{\max},\omega_{\max}$ で飽和処理（最適化の制約と重複させた二重化）。

**比較の公平性を担保する構造**：経路読み込み、参照点生成（前方 0.15 m の先行点）、誤差計算、ゴール判定、速度指令の入出力はすべて ROS 非依存の共通モジュール `follower_core.py` に置き、**4条件の差分は目的関数のみ**に限定されている。

## 5. 実験系（第4章。副次的貢献だが発表で1枚使う価値あり）

### 5.1 オドメトリ評価の限界 —— なぜ外部真値計測が必要か

差動二輪のオドメトリは左右輪の回転量から自己位置を積算するため、**車輪の空転・横滑りは原理的に観測できない**。
深刻なのは、**制御器が自らのオドメトリ上で誤差を最小化する**点である。

> オドメトリ基準の RMSE が測っているのは、**制御器が自分の信じる世界でどれだけ上手くやったか**であって、物理的な追従精度ではない。

**同一走行を3通りで計測した結果（2026-07-16、1 m L字、L2条件）**：

| 計測 | $x$ | $y$ | $\theta$ | 手実測との差 |
|---|---:|---:|---:|---|
| 手実測（メジャー） | 93 cm | 97 cm | 4° | — |
| カメラ真値 | 92.8 cm | 94.5 cm | 5.6° | **2.5 cm / 1.6°** |
| odom（相対値） | 100.9 cm | 97.5 cm | 0.1° | 7.9 cm / 3.9° |

odom は $x$ 方向 **+7.9 cm の滑りを見逃し**、向きも「0.1°（ほぼ完璧）」と報告するが実際は 4° 傾いている。
さらに本研究では **L1 系がコーナーで急峻な操舵を打つため、L2 より滑りやすい条件を自ら作っている**。odom だけで評価すればこの差は原理的に観測できない。

### 5.2 構築した計測系

- 床から見下ろす **Web カメラ（Logicool C270）1台 + AprilTag（36h11）**。床に基準タグ4枚、ロボット上面に1枚
- 2段構成：床基準タグから **solvePnP でカメラ外部姿勢を推定** → ロボットタグから機体姿勢を復元
- **タグ自動サーベイ**：タグを適当に置いて1コマ撮影 → 各タグを PnP → 床平面拘束で中心座標を復元 → タグ自身が原点と軸を定義 → 設定 YAML を自動生成。**メジャー実測を廃止**（自宅環境で毎セッション全撤収するため固定設営が維持できない、という現実的制約への対応）
  - 合成テストで floor_tags 復元 最悪 0.57 cm、robot_pose への伝播 0.033 cm / 0.0016 rad
  - 実機初回サーベイで RMS 0.41 px、静置照合はメジャー実測と +0.5/−1.3 cm 一致
- **誤りを黙って通さない検査**：再投影残差 2 px 超で例外（タグ移動・古い YAML・解像度不一致を検出）
- **自動原点復帰（homing）**：TURN→GO→ALIGN、±3 cm/±2° 精度。sim 90本（遅延0.3 s・パケットロス10%込み）で全収束を確認
- **全自動バッチ実験系**：一括許可 → 走行 → 真値CSV記録 → 原点復帰 → 次走行

**設計上の教訓（発表で使える）**：床タグは**コースを囲む配置**にすること。片側偏在だとゴールが外挿地帯になり 10〜15 cm 誤差が出る。

## 6. 中心的なストーリー（第5章＝論文の心臓部）

**発表の主軸はここ。5ステップで一続きに語る。**

### Step 1: 実現可能性ゲート —— RPi4 で毎周期解けるか

RPi4 上で QP 求解時間を $N$ ごとに実測（各 $N$ で200回、先頭20回はウォームアップ除外、低電圧アラーム発報0を確認＝電源律速でない）。

| $N$ | L2 p95 | L1 p95 | 周期内 |
|---:|---:|---:|:--:|
| 5 | 17.5 | 10.6 | ○ |
| 15 | 16.6 | 18.0 | ○ |
| 30 | 17.7 | 29.2 | ○ |

→ **$N\le30$ で 0.1 s 周期内**。ただし実走行では LiDAR(30Hz)・odom積算・rosbag が同時に動くため p95 は 1.3〜2.8 倍に増える。余裕を見て $N=15$ 常用。

**ここで伏線**：**L1 は L2 より求解が重い。しかもその差は経路依存**。直線では p95 比 1.14〜1.15 倍にすぎないが、**L字では 1.78〜1.92 倍に開く**。操舵が必要で $L^1$ 項が実際に働く条件でこそ計算コストが顕在化する。
**求解時間はそのまま指令の遅れとして閉ループに入る → L1 は自らの入力遅延を増やす方向に働く。**

### Step 2: チャタリングの発現と定量診断

L字経路（直線1.5 m → 左90° → 直線1.5 m）で L1-MPC を実機走行させたところ、**コーナーから走行終了まで $\pm2.0$ rad/s の間を往復し続けた**。

診断指標を4つ定義した：**符号反転回数**／**最大 $|\omega|$**／**飽和率**（$|\omega|>1.5$ の時間割合）／**ゼロ率**（$|\omega|<0.05$ の時間割合）。

| 手法 | 符号反転 | 最大 $|\omega|$ | 飽和率 | ゼロ率 |
|---|---:|---:|---:|---:|
| Kanayama | 0回 | 0.33 | 0 % | 65 % |
| L2-MPC | 0回 | 1.67 | 2 % | 88 % |
| L1-MPC | **15回** | **2.00（上限）** | **41 %** | 50 % |

→ 目視の「ジグザグ」は主観ではなく、**符号反転回数と飽和率という指標の上で2桁の差として分離できる**。
→ **入力を疎にするはずの手法が、最も疎でない挙動を示した**（ゼロ率が4条件中最低）。

### Step 3: 原因の特定 —— 遅延注入による定量再現（本研究の白眉）

**理想シミュレーションでは L1 はチャタらない**（$\Sigma|u|=4.41$、符号反転0）。
→ 原因は sim に無く実機にあるもの。候補：①入力遅延 ②odom雑音 ③未モデル化の摩擦・滑り。

**①を疑う根拠2つ**：
1. L1 の求解時間は L2 の約2倍（p95 で 89.7 対 46.6 ms）＝**チャタった手法だけが大きな遅延を自ら生んでいる**
2. bang-bang 的な切替入力が遅延を伴う閉ループで限界振動を生じることは、**スライディングモード制御で古典的に知られた現象**

実機の遅延量を「求解 p95（約90 ms）＋通信＋車体側速度ループ」から**約200 ms＝制御周期2ステップ**と見積もった。

**検証：差動二輪シミュレータに純粋な入力むだ時間を注入**

| 条件 | 遅延0 | 遅延1 | 遅延2 | 遅延3 | 遅延4 |
|---|---|---|---|---|---|
| L2 $\Sigma\|u\|$/反転 | 4.54/0 | 4.52/0 | 4.52/0 | 4.55/0 | 4.70/1 |
| L1 $\Sigma\|u\|$/反転 | 4.41/0 | 4.94/2 | **18.49/19** | 20.76/14 | 22.63/11 |
| L1 飽和率 | 4 % | 4 % | 36 % | 41 % | 44 % |
| L1 ゼロ率 | 95 % | 93 % | 56 % | 51 % | 50 % |
| **実機実測（参考・n=1）** | — | — | **20.71/15** | — | — |

（n=3 のバッチ値は 19.17 / 18回。どちらで比べても sim の 18.49 / 19回 とほぼ一致する）

→ **遅延2ステップで sim と実機がほぼ定量的に一致**（飽和率も sim 36 % 対 実機 41 %）。
→ 一方 **L2 は遅延3ステップまで符号反転0、4ステップでも1回**。極めて頑健。**壊れるのは切替型の入力を持つ L1 だけ**。

**特定した機序**：
> $L^1$ 正則化が生む bang-bang 的な切替入力は、入力遅延を伴う閉ループにおいて限界振動（スライディングモード的チャタリング）に転じる。

**破綻はしきい値的**：遅延1ステップまでは無事（反転2回）、2ステップで急激に崩れる。実機の遅延はちょうどこの境界を越えていた。
遅延3・4ステップでは符号反転が減る（19→14→11）が $\Sigma|u|$ と飽和率は増え続ける → **振動が消えたのではなく、より粗く振幅の大きい振動へ移行している**。符号反転だけ見ると改善に見えるので $\Sigma|u|$ と飽和率の併記が必要。

**補助資料**：$\dot{x}=-\mathrm{sign}\,x(t-\tau)$ を数値的に解くと、$\tau=0$ で原点収束、$\tau>0$ で**振幅が $\tau$ に比例する極限閉軌道**になる。上記機序と同型であることが一目で分かる図を用意済み。

### Step 4: 対策の設計と、$w_{ms}=2.0$ を選んだ理由

移動抑制項（4.5節）を導入。**重要なのは重みの選び方の論理**：
遅延2ステップの条件では $w_{ms}=0.5$ でもほぼ同等（符号反転 2回 対 1回）。差は**遅延を伸ばしたときに現れる**：

| $w_{ms}$ | 遅延2ステップ | 遅延4ステップ |
|---|---|---|
| 0.5 | 反転2回 | $\Sigma\|u\|=16.16$・反転9回（**チャタへ逆戻り**） |
| 2.0 | 反転1回 | $\Sigma\|u\|=7.52$・反転4回（**保つ**） |

→ **$w_{ms}=2.0$ が買っているのは、その時点の性能ではなく「遅延マージン」である。**

**対策の限界（正直に述べる）**：移動抑制は遅延を無効化するのではなく**破綻を遅らせるだけ**。$w_{ms}=2.0$ でもゼロ率は遅延とともに 93 % → 69 % に低下する。

### Step 5: 実機検証

実機バッチ（4条件 × 3本、**12/12 到達**）で、**符号反転 18回 → 1回、$\Sigma|u|$ 19.17 → 5.02**。チャタリング消失。

**そして最も重要な点：スパース性が失われていない。**
$\omega$ ゼロ率は **0.882** で、L2-MPC の 0.872 を上回り4条件中最良。
対策後も**最大 $|\omega|$ は上限 2.0 rad/s に達している**。変わったのは**上限に張り付く時間（飽和率 37.6 % → 3.9 %）**だけ。
→ 移動抑制は**振幅を制限したのではなく、上限に張り付く時間を縮めた**。3.5節の設計意図（bang-off-bang は保つ）が実機で成立している証拠。

## 8. 考察 —— 何を買い、何を払ったか（第7章）

| | 内容 | 定量値 | 対 L2 |
|---|---|---|---|
| **買っているもの** | 入力のスパース性 | $\omega$ ゼロ率 0.882 | +0.010（ほぼ同等） |
| | 最終姿勢の精度 | $\|\theta\|$ 5.0 ± 4.6° | L2 19.0 ± 3.0°（約3.8倍良い） |
| **払っているもの** | 追従精度（odom） | 2.20 ± 0.05 cm | +0.37 cm |
| | 終点精度（真値） | 21.17 ± 11.56 cm | +8.50 cm |
| | 計算負荷 | 解 p95 31.0 ms | 約1.47倍 |
| | 終点のばらつき | $\sigma$ = 11.56 cm | L2 $\sigma$ = 1.01 cm |

### 8.1 位置精度と姿勢精度のトレードオフ仮説

L2 は二次形式コストにより位置誤差・姿勢誤差を同時かつ連続的に詰めようとし、終端では位置を優先して姿勢に定常残差を残す。
一方 L1 系は補正がゼロに張り付く区間を持つため、終端付近では「動かさない」状態が続き**直前の姿勢がそのまま保たれる**。
提案手法の $\omega$ ゼロ率が最も高いことと、最終向きが最も揃っていることは**同じ性質の2つの現れ**である可能性が高い。
【未検証】この仮説の検証には、終端で特定の向きを要求する経路での比較が必要。

**応用上の意味**：農業用ロボットでは畝の終端で次の作業姿勢へ接続する場面がある。終点位置が数 cm ずれるより、**機体の向きが 20° 傾いているほうが次工程への影響が大きい**状況は現実的にありうる。

### 8.2 計算コストは「安定性の問題」でもある（本研究の一般的貢献）

求解時間はそのまま入力遅延の一部を構成し、その遅延がチャタリングの原因になる。
すなわち **L1 は「計算が重い」という性質によって「自らの安定性を損なう」**。自己増幅ループ：

1. 求解が重い → 入力遅延が増える
2. 入力遅延が増える → bang-bang 入力が限界振動化する
3. 限界振動が起きる → 前周期の解が次周期の初期値として役に立たない
4. warm start が効かない → 求解がさらに重くなる（→1へ）

最後の1段は表C の観察（素のL1は p50 同等・p95 だけ重い）と整合する。
→ **スパース制御を低計算資源プラットフォームで用いる際、計算コストは「周期内に収まればよい」という性質のものではない。周期内に収まっていても、その大きさが安定性に影響する。**
これは L2-MPC のような平滑な最適制御には現れない、**切替型の制御に固有の問題**である。

### 8.3 sim-to-real の予測性について（方法論的知見）

sim と実機の全16組を計算し直した結果：**$\Sigma|u|$・ゼロ率・符号反転は ±7 % 以内で一致**するが、**RMSE は実機が sim より +11.8〜+20.8 % 悪い側**（Kanayama のみ +0.6 %）。
ただし RMSE の絶対差は全条件 0.4 cm 以内（相対差が大きいのは MPC 系の RMSE が元々 1.5〜3 cm と小さいため）。
→ **「sim が当てたのは入力の打ち方であって、追従精度の絶対値ではない」**と区別して述べる。

### 8.4 単一条件での最適化という落とし穴（7.4.1節・質疑で強い）

$\lambda \times w_{ms}$ の2次元グリッド探索を**遅延2ステップの条件だけで**行うと「$\lambda=2, w_{ms}=0.5$ が全指標最良」という結論が出る。
しかしこれは**遅延2ステップでのみ現れる偶然の谷**であり、遅延 0/1/3/4 ステップでは RMSE が 11〜14 cm に悪化する。
同様に「$w_{ms}$ は 0.5 で足りる」という読みも、遅延4ステップで 0.5 が崩壊することで否定された。

→ **単一条件での最適化は見かけの最適を掴む。** しかもこの罠は**条件を完全に制御できる sim だからこそ嵌まりやすい**（実機なら条件が勝手に振れるので、再現性の低さとして露見する）。

## 9. 貢献（3点）

**(1) スパース最適制御の実機適用における具体的な障害と、その解決法を示した。**
理論上は最適である bang-off-bang 入力が実機の入力遅延下で限界振動に転じるという機序を同定し（実機 $\Sigma|u|$ 4.1倍・符号反転18回 → 遅延注入 sim で 18.49・19回と定量再現）、入力変化率ペナルティという最小限の変更で対処できることを実機で示した（18回→1回、19.17→5.02、**ゼロ入力率 0.88 は維持**）。**この障害は既存のシミュレーション研究では現れない性質のものである。**

**(2) 計算コストが安定性の問題であることを示した。**
$L^1$ 化は求解を重くし（操舵を要する経路で L2 の約1.8倍）、その求解時間は入力遅延の一部として閉ループに戻る。計算コストは可解性の問題であると同時に**安定性の問題**である。低計算資源プラットフォームに切替型制御を載せる際の一般的注意事項として提示できる。

**(3) 外部真値計測系を構築し、オドメトリ評価の限界を実証した（副次的貢献）。**
真値による誤差は odom 基準の 6.9〜9.6 倍に達し、直線経路では両者で手法の優劣が逆転する事例も観測された。構築した計測系（俯瞰カメラ + AprilTag、手実測と 2.5 cm・1.6° 一致）とタグ自動サーベイによる設営手順は、同種の実験を行う後続研究に再利用可能である。

> **本研究は提案手法が総合的に優れていると主張していない。** 追従精度・終点精度・計算負荷のいずれも L2-MPC が最良であり、提案手法が最良なのはゼロ入力率と最終姿勢精度の2軸。この結果は隠さず報告する。

## 11. 想定質問と回答（口頭試問対策）

**Q1. なぜ $L^0$ ではなく $L^1$ を解くのか。等価性の条件は？**
→ $L^0$ 最小化は組合せ的で直接解けない。一定の**正規性条件**の下で $L^1$ 最小化と等価になることが知られており、$L^1$ は凸なので実時間で解ける。**⚠ 正規性条件の正確な定義・定理の主張・定理番号は原典で確認しておくこと（最も突かれやすい箇所）。**

**Q2. なぜ入力 $u$ ではなく補正 $\delta u$ を疎にするのか。**
→ 経路追従では参照速度 $v_r\ne0$ なので、$u$ を疎にすると $v=0$ の時間が最大化されロボットが止まってしまう。$\delta u$ を疎にすれば $\delta u=0$ の区間は「参照速度のまま巡航」となり、経路追従において意味のあるハンズオフになる。

**Q3. スパース性の指標をなぜ $\delta\omega$ だけで測るのか。**
→ 入力行列の構造上 $\delta v$ と $\delta\omega$ が完全分離し、$\delta v$ 側の部分問題は退化する（終端制約が1本だけで最小解が無数）。**$\delta v$ のスパース性はソルバ依存であり問題の性質ではない**ため、$\delta\omega$ で測るのが正当。

**Q4. チャタリングの原因が入力遅延だと、どこまで言い切れるのか。**
→ ①理想 sim では起きない ②遅延を注入すると起きる ③**遅延2ステップで $\Sigma|u|$・符号反転・飽和率のすべてが実機実測とほぼ一致する** ④L2 は同じ遅延で壊れない、の4点。ただし**遅延量そのものの直接実測は未実施であり、200 ms は推定値**である点は正直に述べる。

**Q5. 移動抑制項はスパース性を壊さないのか。**
→ 二次ペナルティで $L^1$ 項とは独立に働き、抑制するのは変化率であって大きさではない。実測でも**対策後の最大 $|\omega|$ は上限 2.0 rad/s に達しており、変わったのは上限に張り付く時間（37.6 %→3.9 %）だけ**。ゼロ入力率 0.882 は4条件中最良。

**Q6. 結局 L2-MPC のほうが良いのでは？**
→ **その通りで、総合成績では L2-MPC が最良**である（5軸中3軸）。本研究はそれを隠さず報告している。提案手法が最良なのはゼロ入力率と最終姿勢精度の2軸で、後者は L2 の約3.8倍の差であり僅差ではない。用途に応じて選択されるべき性格の手法である。加えて、**無外乱・平坦床では L2 も既に十分疎**（ゼロ率 0.872）であり、スパース制御の想定利点が現れるはずの外乱条件は未評価。

**Q7. なぜ精度評価にオドメトリを使わないのか。**
→ オドメトリは車輪の滑りを原理的に観測できず、しかも**制御器は自らのオドメトリ上で誤差を最小化する**。実測で真値誤差は odom の 6.9〜9.6 倍、9走行すべてに現れた「コーナー外側への流れ」という系統誤差が odom には一切現れない。特に**L1 系は急峻な操舵で自ら滑りやすい条件を作る**ため、odom 評価では手法間の差が原理的に見えない。

**Q8. $\lambda=0.3$、$w_{ms}=2.0$、$N=15$ の根拠は？**
→ 表（4.6節）参照。特に $w_{ms}=2.0$ は「その時点の性能」でなく「**遅延マージン**」で選んでいる点を強調する。$N$ は RPi4 の実測求解時間から上限が決まる。

**Q9. 重み $Q=\mathrm{diag}(10,10,1)$ の根拠は？**
→ **経験的な設定である**（正直に述べる）。感度解析は sim で完結するため今後可能。

**Q10. この知見はこのロボットに固有か、一般化できるか。**
→ 機序は「bang-bang 的な切替入力 × 入力遅延 → 限界振動」であり、これはスライディングモード制御で古典的に知られた現象と同型である。したがって**bang-off-bang 構造を持つ制御一般に当てはまると考えられる**。**⚠ この一般化には文献の裏づけを用意しておくこと（7.3節、突かれやすい）。**

**Q11. 実機実験の反復数が3本と少なくないか。**
→ 少ない。実際、提案手法の終点誤差は3本中1本が外れており、偶発か系統かを判別できていない。カメラ真値パイプラインで計測は自動化済みなので、反復数の増加は実験時間の問題のみである。

**Q12. 大学院で何をやりたいか（必ず聞かれる）**
→ **この欄は発表者本人が埋めること。** 本研究から自然に伸びる方向としては：①外乱・不整地条件でのスパース制御の評価（本研究の最大の欠落） ②遅延補償と移動抑制の統合的設計 ③非線形 MPC における「求解時間↔安定性」トレードオフの定式化 ④実機で成立する制御設計における計測系・評価系の方法論。**AI に志望動機を書かせないこと。**

## 13. 用語ミニ辞典（聴衆に説明が要る語）

| 用語 | 説明 |
|---|---|
| **最大ハンズオフ制御** | 入力の大きさではなく「入力がゼロである時間」を最大化する制御設計論。$L^0$ ノルム最小化として定式化される |
| **bang-off-bang** | 入力が上限・ゼロ・下限の3値のみを取る構造。$L^1$ 最適解が持つ性質 |
| **MPC（モデル予測制御）** | 未来 $N$ ステップの挙動を予測して最適化問題を解き、その先頭だけを実行して毎周期解き直す制御 |
| **チャタリング** | 制御入力が高速に符号を反転し続ける現象。スライディングモード制御で古典的に知られる |
| **ゼロ入力率** | $|\omega|<0.05$ rad/s であった時間の割合。ハンズオフの度合いを表す |
| **飽和率** | $|\omega|>1.5$ rad/s であった時間の割合。上限（2.0）に張り付いている度合い |
| **オドメトリ（odom）** | 車輪の回転量から自己位置を積算する手法。滑りは原理的に観測できない |
| **AprilTag** | 白黒の2次元マーカー。カメラ画像から位置姿勢を高精度に推定できる |
| **warm start** | 前回の解を次回の最適化の初期値に使い、求解を高速化する手法 |
| **Kanayama 法** | 移動ロボットの経路追従における古典的な非線形フィードバック則。解析的に入力を決める |
