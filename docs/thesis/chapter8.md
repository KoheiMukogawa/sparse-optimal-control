## 8.1 結論

本研究は、農業用途の小型移動ロボットにおける経路追従制御に
最大ハンズオフ制御（$L^1$ 正則化による スパース最適制御）を適用し、
**スパース制御を実機で成立させる条件は何か**を問うた。

本論文の結論は次のとおりである。

> **入力遅延に対する明示的な配慮が、スパース制御を実機で成立させるための必須条件である。**

この結論に至る過程は次のように要約される。

**(1) 素朴な $L^1$-MPC は実機で破綻した。**
シミュレーション上では良好に動作する $L^1$-MPC（$\lambda = 0.3$）を実機に適用したところ、
L 字経路のコーナーにおいて bang-bang 的なチャタリングが発生した。
入力の積算 $\Sigma|u|$ は L2-MPC の **4.1 倍**（$19.17$ 対 $4.65$）、
$\omega$ の符号反転は **18 回**（L2 は 0 回）であり、
走行時間の 37.6 % を角速度上限付近に張り付いた状態で費やした。
$\omega$ ゼロ率は $0.529$ と 4 条件中で最低であり、
これは「必要なときだけ動かす」というハンズオフの狙いと正反対の結果である。
すなわち**スパース制御を素朴に実装すると、最もスパースでない制御になる**。

**(2) 原因は入力遅延であり、その機序をシミュレーションで定量的に再現した。**
理想シミュレーションでは同じ制御則がチャタリングを起こさない（符号反転 0 回）ことから、
原因はシミュレーションに無く実機にあるもの、すなわち
求解・通信・車体側速度ループの遅延であると仮説を立てた。
差動二輪シミュレータに入力遅延を注入したところ、
**遅延 2 ステップ（約 200 ms）において $\Sigma|u| = 18.49$、符号反転 19 回**となり、
実機実測とほぼ定量的に一致した。
この破綻はしきい値的であり、遅延 1 ステップまでは無事（符号反転 2 回）である一方、
2 ステップで急激に崩れる。実機の遅延はちょうどこの境界を越えていた。
一方 L2-MPC は遅延 3 ステップまで符号反転 0 を保ち、遅延 4 ステップでも 1 回に留まる。
**壊れるのは切替型の入力を持つ L1 だけである。**

**(3) 入力変化率へのペナルティにより、スパース性を保ったままチャタリングを除去した。**
対策として、入力の**大きさ**ではなく**変化率**に二次ペナルティを課す移動抑制項を導入した。
実機バッチ（4 条件 × 3 本、12/12 到達）において、
符号反転は **18 回から 1 回**へ、$\Sigma|u|$ は **19.17 から 5.02** へ減少し、
チャタリングは消失した。
重要なのは、**この対策がスパース性を損なわなかった**ことである。
$\omega$ ゼロ率は $0.882$ であり、L2-MPC の $0.872$ を上回って 4 条件中最良である。
抑制したのは入力の変化率のみであるため、
「必要なときに大きく動かす」bang-off-bang の性格は保たれている。
実際、対策後も最大 $|\omega|$ は上限の $2.0$ rad/s に達しており、
変わったのは上限に張り付く時間（37.6 % → 3.9 %）である。

**(4) ただし総合成績において提案手法は L2-MPC に及ばない。**
追従精度（odom RMSE $1.83$ 対 $2.20$ cm）、
真値による終点誤差（$12.67$ 対 $21.17$ cm）、
計算負荷（求解 p95 $21.1$ 対 $31.0$ ms）のいずれも L2-MPC が優れる。
提案手法が最良となるのは、**ゼロ入力率**（$0.882$）と
**最終姿勢の精度**（$|\theta| = 5.0 \pm 4.6°$、L2 は $19.0 \pm 3.0°$）の 2 軸である。
勝っている軸と負けている軸は明確に分かれており、
提案手法は「総合的に優れた制御則」ではなく、
**入力の疎さと終端姿勢を重視する用途において選択されるべき手法**である。

### 本研究の貢献

以上を踏まえ、本研究の貢献を 3 点に整理する。

**第一に、スパース最適制御の実機適用における具体的な障害と、その解決法を示した。**
理論上は最適である bang-off-bang 入力が、
実機の入力遅延の下では限界振動に転じるという機序を同定し、
入力変化率ペナルティという最小限の変更で対処できることを実機で示した。
この障害は既存のシミュレーション研究では現れない性質のものである。

**第二に、計算コストが安定性の問題であることを示した。**
$L^1$ 正則化は L2 に比べて求解が重く（L 字経路で p95 約 1.8 倍）、
その求解時間は入力遅延の一部を構成する。
すなわち**計算コストは可解性の問題であると同時に安定性の問題である**。
低計算資源のプラットフォームにスパース制御を載せる際の一般的注意事項として提示できる。

**第三に、副次的な貢献として外部真値計測系を構築した。**
オドメトリ基準の評価は滑りを観測できず、
本研究では真値の誤差がオドメトリ基準の $6.9 \sim 9.6$ 倍に達した。
直線経路では両者で手法の優劣が逆転する事例も観測された。
AprilTag を用いた俯瞰カメラによる真値計測系（手実測と $2.5$ cm・$1.6°$ で一致）と、
タグの自動サーベイによる設営手順は、同種の実験を行う後続研究に再利用可能である。

## 8.2 今後の課題

本研究には第7.6 節に述べた限界がある。その解消手段を課題として整理する。

**(1) 外乱条件での評価。**
本研究の実験はすべて無外乱・平坦床・無積載の条件で行われた。
スパース制御の想定利点——補正入力がゼロに張り付くため微小外乱に反応しない——は
外乱下でこそ現れるはずであり、**本研究はこの主要な想定利点を検証できていない**。
積載質量を 0 / 500 / 1000 g と変えたバッチ（27 走行）の実験条件は整備済みであり、
実機の復旧後ただちに実施できる。
路面材の変更（人工芝・土などの圃場模擬）も同様に必要である。

**(2) 入力遅延の直接計測。**
本研究の中心的主張の根拠である「約 200 ms」は推定値である。
角速度のステップ指令に対する車体応答の立ち上がり時刻差を
カメラ真値によって計測すれば、推定値を実測値に置き換えられる。
これは本論文の主張の核を直接裏づける最も価値の高い追加実験である。

**(3) 遅延マージンの実機検証。**
第5.7 節で述べた「$w_{ms} = 2.0$ が買っているのは遅延マージンである」という主張は、
現時点ではシミュレーションによるものである。
実機の遅延量は固定であるため通常の実験では検証できないが、
**制御ノードに指令バッファを追加して人工的に遅延を注入すれば直接検証できる**。
シミュレーションの予測（$w_{ms} = 0.5$ は遅延 +2 ステップで崩壊し、$2.0$ は保つ）と
突き合わせることで、本研究の設計根拠を実機で閉じられる。

**(4) 遅延補償という別解との比較。**
本研究は移動抑制によって遅延に対処したが、
既知の遅延分だけ状態を予測してから求解する遅延補償も原理的な対処法である。
移動抑制が破綻を遅らせるにとどまる（$w_{ms} = 2.0$ でも
ゼロ率は遅延とともに 93 % → 69 % に低下する）のに対し、
遅延補償は遅延そのものを打ち消しうる。両者の比較は自然な発展である。

**(5) 消費電力の直接計測。**
$\Sigma|u|$ は消費エネルギーの代理指標にすぎない。
電流センサによる実測を行い、この代理が妥当であるかを検証する必要がある。
妥当でなければ、本論文で「消費エネルギー」と呼んでいる量は
「操舵量」と改めるべきである。

**(6) 反復数の増加。**
提案手法の終点誤差は 3 本中 1 本が外れており（$34.5$ cm、他 2 本は $14 \sim 15$ cm）、
n=3 ではこれが偶発的か系統的かを判別できない。
第4.5 節で構築したカメラ真値パイプラインにより計測が自動化されているため、
反復数を増やすことは実験時間の問題のみである。

**(7) 非線形 MPC との比較。**
本研究は参照軌道まわりで線形化した誤差ダイナミクスに基づく凸最適化として定式化した。
CasADi と IPOPT による非線形 MPC として定式化すれば線形化誤差を回避できるが、
求解時間は増大する。本研究の知見に照らせば、
**求解時間の増大は遅延を通じて安定性に跳ね返る**ため、
このトレードオフ自体が検討に値する研究課題である。

これらのうち (1)〜(3) および (6) は、実機が復旧すれば本研究の枠組みのまま実施できる。
実験条件・バッチランナー・真値計測系はいずれも整備済みであり、
追加で必要なのは実験時間のみである。

## 著者が確認・補完すべき箇所

1. **8.1 節 (1) の「L2 の 4.1 倍」は n=3 の値である。**
   2026-06-13 の単発走行では $20.71$ 対 $4.54$ で **4.6 倍**であった。
   第5.4 節では単発値（4.6 倍）を、本章では n=3 の値（4.1 倍）を用いている。
   **論文全体でどちらを代表値とするかを統一すること。**
   n=3 を採るのが妥当と考えられる（第7.6 節の限界 7 の方針と整合する）。

2. **同様に符号反転回数も 15 回（n=1）と 18 回（n=3）が混在する。**
   本章は n=3 の 18 回を用いている。第5章では両方を提示している。

3. **8.1 節の「貢献」の書き方を指導教員と確認すること。**
   卒業論文において貢献を 3 点に明示的に整理する構成が適切かは、
   分野・研究室の慣行による。
   不要であれば結論の (1)〜(4) のみとし、貢献の節を削ってよい。

4. **8.2 節 (7) の非線形 MPC は当初の実装計画に含まれていた。**
   `CLAUDE.md` の実装スタックには CasADi + IPOPT が挙がっているが、
   本研究では cvxpy + OSQP による凸定式化のみを実施した。
   この経緯を第1章（研究の範囲）または本節で明示するかを判断すること。

5. **第7.6 節との重複を確認すること。**
   限界（7.6 節）と課題（8.2 節）は対応関係にある。
   分量が許さない場合はいずれかへ統合する。
