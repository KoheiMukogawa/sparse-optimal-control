# 環境構築 —— 2台のPCで同じ研究環境を作る

自作機（WSL2）と MacBook の2台で作業する。**どちらでも同じことができる**状態を保つための
手順と、PC固有になりやすい箇所の一覧。2026-11-12 作成。

## 1. 何がどこにあるか

| 置き場所 | 中身 | 同期方法 |
|---|---|---|
| `KoheiMukogawa/sparse-optimal-control`（**public**） | コード・`configs/`・`docs/`・`scripts/` | git |
| `KoheiMukogawa/sparse-optimal-control-results`（**private**） | `results/` の中身（実機の rosbag・CSV・図、54MB） | git |
| 各PCのローカル | `.venv/`・`scripts/hosts.env`・`data/paper/` | 同期しない（下記で各自作る） |

`results/` は**本体の作業ツリーの中に clone した別リポジトリ**。本体は public で、
実機データは未発表・`data/paper/` は他者の著作物なので、公開側には入れられない。
作業ツリー上は1つに見えるが、**git としては2つある**ことを忘れないこと。

## 2. 新しいPCでの手順

### 2.1 前提ツール

```sh
# macOS
brew install git gh uv
# WSL / Ubuntu
sudo apt-get install -y git && curl -LsSf https://astral.sh/uv/install.sh | sh
#   gh は https://cli.github.com/ の手順で入れる
```

LaTeX は卒論・概要をビルドするときだけ必要（§4）。**ROS2 は要らない**（§3）。

### 2.2 GitHub 認証（HTTPS + gh に統一する）

```sh
gh auth login          # HTTPS を選ぶ
gh auth setup-git      # git が gh のトークンを使うようにする
```

> **SSH 鍵を各PCで管理しないこと。** 2026-11-12 に、ラップトップの鍵をコピーしただけで
> GitHub に登録されていない自作機から **push が一度も通っておらず、2台のPCが分岐していた**
> （本体15コミット・results 約2ヶ月分が片方にしか無かった）。HTTPS なら `gh` の認証が
> そのまま効く。

### 2.3 クローン

```sh
git clone https://github.com/KoheiMukogawa/sparse-optimal-control.git
cd sparse-optimal-control
git clone https://github.com/KoheiMukogawa/sparse-optimal-control-results.git results
uv sync --frozen
```

`results` を本体の中に clone するのが要点（本体の `.gitignore` が `results/` を
除外しているので、公開側は中身に気づかない）。

### 2.4 動作確認

```sh
uv run pytest tests/                                    # 172 passed なら成功
uv run python rover/test_mpc_sim.py --reg l1 --lam 0.3  # L1-MPC の sim
```

`172 passed` は `results/` がある状態の数。clone しないと実機データに依存するテスト
（`tests/test_analyze_bag.py`・`tests/test_thesis_data.py`）が skip される。

### 2.5 実機を触る場合だけ

```sh
cp scripts/hosts.env.example scripts/hosts.env
$EDITOR scripts/hosts.env      # IP とユーザ名を入れる（このファイルは追跡しない）
scripts/connect_rpi.sh         # 接続確認
```

### 2.6 概要（LaTeX）を書き直す場合だけ

学会配布の書式は public に置けないので private 側に退避してある。

```sh
cp results/_abstract_style/*.cls results/_abstract_style/*.sty docs/abstract/
```

先輩の完成サンプル（`abstract.tex` ほか）は**どちらのリポジトリにも無い**
（他の学生の氏名・学籍番号を含むため）。必要なら指導教員に再配布を依頼する。

## 3. 手元のPCに ROS2 は要らない

2026-07-17 に「**laptop↔RPi の DDS 通信は元々不要**」と確認済み（`docs/handoff.md`）。

- 走行中の制御は **RPi 内で完結**する（`mpc_follower.py` は RPi で動く）
- 手元のPCからは **SSH**（`rover/exp_backends.py` が `ros2` コマンドを SSH 越しに叩く）と
  **素の UDP**（`rover/homing.py` → RPi の `udp_twist_bridge.py`）しか使わない
- `rclpy` を import するのは RPi 側で動くノードだけ。`uv sync` の依存に `rclpy` は無い
- bag 解析の `rosbags` は **pure Python** なので ROS2 無しで動く

したがって **MacBook でも実機バッチ・bag解析・図生成・卒論執筆のすべてができる**。
ROS2 Humble を macOS に入れる必要はない。

## 4. macOS 固有の注意

- **日本語ファイル名**: このリポジトリは `docs/作業記録/` など日本語パスが多い。
  macOS は濁点を分解して保持する（NFD）ため、`git status` が常に汚れて見えることがある。
  `git config core.precomposeunicode true`（Git 1.8.5 以降は既定）を必ず確認する
- **大文字小文字を区別しない**ファイルシステムなので、`Fig.png` と `fig.png` を
  別ファイルとして作らないこと
- LaTeX: 卒論・概要は **platex + dvipdfmx**（pdflatex ではない）。
  `brew install --cask mactex-no-gui` で入る
- 日本語フォントは `japanize-matplotlib`（依存に入っている）が面倒を見る。
  mac 固有のフォント指定をコードに書かないこと
- `uv.lock` は macOS の wheel を含む universal lock なので `uv sync --frozen` がそのまま通る
  （cvxpy / clarabel / opencv の macosx wheel を確認済み）

## 5. 自作機（WSL2）固有の注意

- `C:\Users\<Windowsユーザ名>\.wslconfig` に `memory=3GB` が残っている。今は効いていないが
  `wsl --shutdown` すると 3GB に絞られる（現在は 15GiB）
- `/mnt/c/...` を参照するコードを書かないこと。唯一の例外は
  `scripts/obsidian_charts.py` で、出力先は環境変数 `OBSIDIAN_CHART_DIR` で外に出してある

## 6. 日々の運用

```sh
scripts/sync.sh pull             # 作業開始時。2つのリポジトリを pull
scripts/sync.sh status           # いま何が未コミット・未 push かを両方まとめて見る
scripts/sync.sh push "メッセージ" # 終了時。results を commit し、2つを push
```

**図を再生成したら results 側も push する。** これを忘れると、もう1台のPCで
古い図のまま卒論を書くことになる（実際に 2026-09-17〜11-11 の間そうなっていた）。

## 7. 属PC化チェック（何かおかしいとき）

```sh
scripts/sync.sh status                  # 2つのリポジトリの ahead/behind
git remote -v                           # https://github.com/... になっているか
git rev-parse --abbrev-ref '@{upstream}' # origin/main が設定されているか
uv run pytest tests/                    # 172 passed か（skip が出たら results が無い）
grep -rn "/home/\|/Users/\|/mnt/c/" --include="*.py" rover/ docs/ scripts/
    # ↑ 絶対パスが混ざっていないか。ヒットして良いのは次の2つだけ:
    #   exp_backends.py の RPI_ROOT（RPi 側のパスなので手元のPCとは無関係）
    #   obsidian_charts.py の /mnt/c（コメントと WSL 用フォント探索。既定値ではない）
```
